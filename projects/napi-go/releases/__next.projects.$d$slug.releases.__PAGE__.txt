15:T14c0,<p>The first release: native Node.js addons written in Go, with the tooling of napi-rs.</p>
<h3 id="framework-layer-2-package-napi"><a class="heading-anchor" href="#framework-layer-2-package-napi">Framework (Layer 2, package <code>napi</code>)</a></h3>
<ul>
<li><code>napi.Export</code> of functions, classes and constants, with generic wrappers (<code>FuncN</code>, <code>FuncEN</code>,
<code>ProcN</code>, <code>ProcEN</code>, <code>AsyncN</code>, <code>AsyncProcN</code>, <code>MethodN</code>, <code>CtorN</code>, …) for up to 8 parameters.</li>
<li>Automatic conversions from the Go types: numbers (integers range-checked), strings, <code>[]byte</code>
(views of JS memory), slices, arrays, maps, structs (<code>napi</code>/<code>json</code> tags), pointers, <code>any</code>,
<code>*big.Int</code>, <code>time.Time</code>, <code>Either[A, B]</code>, napi values, and types implementing <code>FromJS</code>/<code>ToJS</code>.
Conversion errors name the argument and the path inside it.</li>
<li>Asynchronous functions: a <code>context.Context</code> first parameter runs the function in a goroutine and
returns a Promise.</li>
<li>Classes backed by Go values (<code>NewClass</code>), with methods, accessors, statics, <code>Finalize</code>, and the
same JS object for the same <code>*T</code>.</li>
<li><code>JSFunc[A, R]</code>: goroutines call JS functions and receive the converted result.</li>
<li>A C trampoline converts numbers, booleans and short strings and unwraps <code>this</code> with one cgo
crossing per call; no Go allocation per call for primitives, Buffers, methods and accessors.</li>
</ul>
<h3 id="core-layer-1-package-napi"><a class="heading-anchor" href="#core-layer-1-package-napi">Core (Layer 1, package <code>napi</code>)</a></h3>
<ul>
<li>Typed JS values (<code>Value</code>, <code>Object</code>, <code>Function</code>, <code>String</code>, <code>BigInt</code>, <code>Buffer</code>, <code>TypedArray</code>, …),
Go errors thrown as JS exceptions with kind and code, panics as <code>GO_PANIC</code>.</li>
<li>Functions, classes (<code>DefineClass</code>), properties, references, finalizers, <code>Wrap</code>, type tags,
externals, handle scopes, cleanup hooks, instance data per env, zero-copy and external buffers.</li>
<li>Concurrency: <code>Env.Async</code> (Promises settled from goroutines), <code>ThreadsafeFunction[T]</code>,
<code>Env.Context</code> (canceled when the env is destroyed), <code>Ref.DeleteLater</code>; one dispatcher per env
wakes the JS thread once for a batch of results.</li>
<li>Worker threads: the addon loads in every env, with separate state.</li>
</ul>
<h3 id="node-api-bindings-layer-0-package-sys"><a class="heading-anchor" href="#node-api-bindings-layer-0-package-sys">Node-API bindings (Layer 0, package <code>sys</code>)</a></h3>
<ul>
<li>The 154 functions of Node-API 1–10, generated 1:1, resolved at run time from the Node.js process
(no import library, builds without Node.js).</li>
<li>Declared Node-API version 8 by default, 9 and 10 with build tags.</li>
<li>Coexistence of the Go runtime with Node.js signals: <code>SA_ONSTACK</code> added to the handlers Node.js
installs later (Linux), <code>SA_RESETHAND</code> restored for SIGINT and SIGTERM (macOS), and a guard
against a second Go runtime on macOS x64.</li>
</ul>
<h3 id="code-generator-napi-go-gen"><a class="heading-anchor" href="#code-generator-napi-go-gen">Code generator (<code>napi-go gen</code>)</a></h3>
<ul>
<li><code>//napi:export</code>, <code>//napi:class</code>, <code>//napi:constructor</code>, <code>//napi:getter</code>, <code>//napi:setter</code>,
<code>//napi:skip</code>, <code>//napi:object</code>, <code>//napi:type</code>, <code>//napi:returns</code>.</li>
<li>Generates the registrations (<code>zz_napi.go</code>), <code>index.d.ts</code> with the Go comments as JSDoc, and
<code>index.js</code>; reports unsupported types with file and line; <code>-check</code> for CI.</li>
</ul>
<h3 id="cli-cmdnapi-go"><a class="heading-anchor" href="#cli-cmdnapi-go">CLI (<code>cmd/napi-go</code>)</a></h3>
<ul>
<li><code>napi-go new</code>: a project with an annotated example, tests and a GitHub Actions workflow that
builds, tests and publishes every target.</li>
<li><code>napi-go build</code>: targets <code>linux-x64-gnu</code>, <code>linux-arm64-gnu</code>, <code>darwin-x64</code>, <code>darwin-arm64</code>,
<code>win32-x64-gnu</code>, <code>win32-arm64-gnu</code>; cross-compilation from any host with zig (Linux binaries for
glibc 2.17); format check of each binary.</li>
<li><code>napi-go artifacts</code> and <code>napi-go prepublish</code>: one npm package per platform and
<code>optionalDependencies</code>, as napi-rs; <code>index.js</code> loads the binary of the running platform.</li>
</ul>
<h3 id="known-limitations"><a class="heading-anchor" href="#known-limitations">Known limitations</a></h3>
<ul>
<li>musl (Alpine Linux) is not supported by any Go release (golang/go#71953).</li>
<li>macOS x64: one Go addon per process (golang/go#23617).</li>
<li>A call into Go costs about 100 ns on Linux and about 1 µs on Windows; see <code>bench/README.md</code>.</li>
<li>Intermittent failure, under investigation, of one end-to-end signal test on Linux arm64 CI
runners (a hang or a SIGBUS while the test floods every thread with signals).</li>

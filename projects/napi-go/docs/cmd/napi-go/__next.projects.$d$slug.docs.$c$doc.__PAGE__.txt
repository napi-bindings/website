19:T45ec,<h1 id="napi-go-cli">napi-go (CLI)</h1>
<p>Creates, builds and packages Node.js addons written in Go: the equivalent of the <code>napi</code> CLI of
napi-rs.</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> run</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> github.com/napi-bindings/napi-go/cmd/napi-go@latest</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> new</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> my-addon</span></span>

<p>Cross builds use <a href="https://ziglang.org/download/" target="_blank" rel="noreferrer noopener">zig</a> as C compiler (<code>zig cc -target …</code>), from any
host to any target. <code>-zig</code> chooses when:</p>
<ul>
<li><code>auto</code> (default): cross builds, and release builds for Linux, so that the binary needs glibc 2.17
rather than the glibc of the build machine (without zig a warning says so);</li>
<li><code>always</code>: every build (for instance Windows without MinGW);</li>
<li><code>never</code>: the system C compiler (<code>$CC</code>); cross builds then need <code>-cc</code>.</li>
</ul>
<p><code>-cc &#x3C;command></code> sets the C compiler of every target instead. macOS builds the other architecture
with the system clang. For macOS targets built elsewhere, the CLI provides zig with stubs of
<code>libresolv</code> and of the CoreFoundation framework, which Go links and zig does not ship (the real
libraries are loaded at run time).</p>
<p>After each build the format of the binary is checked against the target (ELF, Mach-O or PE,
architecture, shared library), so a wrong <code>$CC</code> fails the build instead of the <code>require()</code>.</p>
<h2 id="the-entry-point"><a class="heading-anchor" href="#the-entry-point">The entry point</a></h2>
<p><code>gen</code> writes <code>index.js</code>, which loads the binary of the running platform, trying in order:</p>
<ol>
<li><code>NAPI_GO_NATIVE_LIBRARY_PATH</code>, if set (its errors are not caught);</li>
<li><code>&#x3C;binaryName>.&#x3C;target>.node</code> and <code>&#x3C;binaryName>.node</code> next to <code>index.js</code> (local builds);</li>
<li>the package <code>&#x3C;name>-&#x3C;target></code> (published builds).</li>
</ol>
<p>If none loads, the error lists each candidate with the reason (<code>not found</code>, <code>package not installed</code>, or the error of <code>dlopen</code>), with the errors as <code>cause</code>. On musl it says that musl is not
supported. <code>index.js</code> ends with the export names in the form <code>0 &#x26;&#x26; (module.exports = { … })</code>,
which Node reads (and never runs) to let ES modules import them by name.</p>
<h2 id="publishing"><a class="heading-anchor" href="#publishing">Publishing</a></h2>
<p>As with napi-rs, every target has an npm package <code>&#x3C;name>-&#x3C;target></code> holding its <code>.node</code> file, with
<code>os</code>, <code>cpu</code> and, on Linux, <code>libc</code>; the main package lists them in <code>optionalDependencies</code> and npm
installs only the one matching the machine.</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> tool</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> napi-go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> artifacts</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -d</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> artifacts</span><span style="color:#6A737D;--shiki-dark:#6A737D">   # find &#x3C;binaryName>.&#x3C;target>.node files (recursively) and copy them to npm/&#x3C;target>/</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> tool</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> napi-go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> prepublish</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -publish</span><span style="color:#6A737D;--shiki-dark:#6A737D">      # versions, optionalDependencies, npm publish of each platform package</span></span>

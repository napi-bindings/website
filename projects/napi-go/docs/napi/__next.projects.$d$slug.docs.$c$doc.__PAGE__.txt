19:Tbc64,<h1 id="napi--layers-1-and-2-of-napi-go">napi — Layers 1 and 2 of napi-go</h1>
<p>Idiomatic Go API on top of Node-API, built on Layer 0 (<code>sys</code>), in two layers that can be mixed in
the same addon:</p>
<ul>
<li><strong>Layer 2, the framework</strong> (napi-rs style): declare Go functions and types and napi-go converts
arguments and results, runs async functions in goroutines and backs JS classes with Go
values. No hand-written callbacks.</li>
<li><strong>Layer 1, the core</strong> (node-addon-api style): typed JS values, Go errors converted into JS
exceptions, callbacks, classes, references and buffers, for full control.</li>
</ul>

<h2 id="layer-2-the-framework"><a class="heading-anchor" href="#layer-2-the-framework">Layer 2: the framework</a></h2>
<p>Instead of writing the registrations by hand, annotate the declarations (<code>//napi:export</code>,
<code>//napi:class</code>) and let <a href="/projects/napi-go/docs/internal/codegen/"><code>napi-go gen</code></a> generate them together with
the TypeScript declarations.</p>
<h3 id="exports"><a class="heading-anchor" href="#exports">Exports</a></h3>
<p><code>napi.Export(name, def)</code> adds an export, created in every env that loads the addon (main thread
and <code>worker_threads</code>), in registration order together with <code>napi.Init</code> functions. <code>def</code> is a
function (<code>FuncDef</code>), a class (<code>*ClassDef[T]</code>) or a constant (<code>napi.Const(v)</code>, converted with
<code>ToValue</code>). A type that cannot be converted makes <code>require()</code> fail with a TypeError naming the
export, the wrapper and the type, not the first call. <code>FuncDef.New(env, name)</code> creates a JS
function at runtime (to return a closure, for instance).</p>

<p>Named types convert like their underlying type (<code>type Celsius float64</code>). Not convertible:
channels, functions, complex numbers, non-empty interfaces (from JS), maps with other key types.</p>
<p><strong>Structs.</strong> The JS name of a field is its <code>napi</code> tag, else its <code>json</code> tag, else the Go name in
lowerCamelCase (<code>UserID</code> → <code>userID</code>, <code>URLPath</code> → <code>urlPath</code>). <code>napi:"-"</code> skips the field,
<code>omitempty</code> leaves zero values out and makes the field optional. Embedded structs are flattened,
as in <code>encoding/json</code>. A field that is <code>undefined</code> is an error unless it is optional: a pointer,
<code>any</code>, <code>napi.Value</code>, or tagged <code>omitempty</code>. Recursive types are supported.</p>
<p><strong>Errors.</strong> A failed conversion throws TypeError <code>ERR_INVALID_ARG_TYPE</code>, RangeError
<code>ERR_OUT_OF_RANGE</code> or <code>ERR_INVALID_ARG_VALUE</code> (the codes Node.js uses for its own argument
checks), with the position of the value:
<code>argument 1: address.tags[2]: expected string, got number</code>. Errors returned by the Go function
follow the Layer 1 rules (table below); a panic becomes <code>GO_PANIC</code>.</p>

<h3 id="async-functions-and-jsfunc"><a class="heading-anchor" href="#async-functions-and-jsfunc">Async functions and JSFunc</a></h3>
<p><code>AsyncN</code> converts the arguments on the JS thread (so a bad argument throws synchronously), runs
the function in a goroutine (<code>Env.Async</code>, with the env context), and converts the result on the
JS thread when the Promise settles. Parameters and results must not contain napi values; <code>[]byte</code>
arguments are copied.</p>
<p><code>NewJSFunc[A, R](env, fn, opts)</code> lets goroutines call a JS function and wait for the converted
result: <code>r, err := f.Call(ctx, arg)</code>. A returned Promise is awaited; JS exceptions and rejections
become an <code>*Error</code> with the JS message, code and kind. It is a threadsafe function (Release,
Abort, Ref/Unref); queued calls return <code>ErrClosing</code> when it is aborted and <code>ErrEnvClosed</code> when
the env is destroyed.</p>
<h3 id="how-it-works-and-what-it-costs"><a class="heading-anchor" href="#how-it-works-and-what-it-costs">How it works, and what it costs</a></h3>
<ul>
<li>
<p><strong>Codecs.</strong> Each Go type gets a codec built once with reflection and cached; at run time it
works on <code>unsafe</code> pointers. Primitives, <code>[]byte</code>, napi values and class pointers are converted
by direct calls, so their Go values stay on the stack: <strong>0 Go allocations per call</strong> for
numbers, booleans, Buffers, methods and accessors (measured in the e2e tests).</p>
</li>
<li>
<p><strong>Typed trampoline.</strong> Functions, methods and accessors use a C trampoline that reads number,
boolean and string arguments (up to 512 bytes in total), unwraps <code>this</code> for methods, and
creates number, boolean and short string results in C: one cgo transition per call. A value
C cannot convert (wrong type, long string) is converted in Go, with the same error messages.</p>

</tbody>
</table>
<h2 id="layer-1-design-choices"><a class="heading-anchor" href="#layer-1-design-choices">Layer 1: design choices</a></h2>
<p><strong>Value carries its env.</strong> <code>Value</code> is <code>{env, napi_value}</code>: two words passed by value, like
<code>Napi::Value</code>. Specialized types (<code>Object</code>, <code>Function</code>, <code>String</code>, <code>Buffer</code>, ...) embed
<code>Value</code>, so they inherit all its methods and <code>x.Value</code> returns the generic value without
conversions. Arguments to <code>Set</code>, <code>Call</code>, and similar methods are <code>Value</code> rather than an interface:
converting a struct to an interface would allocate.</p>
<p><strong>Errors.</strong> Every fallible operation returns <code>error</code>. A status other than <code>napi_ok</code>
becomes a <code>*napi.Error</code> with the message from <code>napi_get_last_error_info</code>, copied immediately (Node
overwrites it on the next call). In JS:</p>
<table>
<thead>
<tr>
<th>Error returned by a callback</th>
<th>Thrown as</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>*napi.Error</code> from a <code>*_expected</code> status</td>
<td><code>TypeError</code>, code <code>ERR_NAPI_&#x3C;STATUS></code> (e.g. <code>ERR_NAPI_NUMBER_EXPECTED</code>)</td>
</tr>
<tr>
<td><code>*napi.Error</code> from another status</td>
<td><code>Error</code>, code <code>ERR_NAPI_&#x3C;STATUS></code></td>
</tr>
<tr>
<td><code>napi.TypeError(code, msg)</code>, <code>RangeError</code>, <code>SyntaxError</code></td>
<td>the corresponding constructor, with code</td>
</tr>
<tr>
<td>error implementing <code>JSCode() string</code></td>
<td><code>Error</code> with that code</td>
</tr>
<tr>
<td>any other <code>error</code></td>
<td><code>Error</code> with message <code>err.Error()</code></td>
</tr>
<tr>
<td><code>napi.Throw(v)</code></td>
<td>the value <code>v</code> as-is</td>
</tr>
<tr>
<td><code>ErrPendingException</code></td>
<td>the already-pending exception, unchanged</td>
</tr>
<tr>
<td>panic</td>
<td><code>Error</code> with code <code>GO_PANIC</code> (handled by <code>sys</code>)</td>
</tr>
</tbody>
</table>
<p>Wrapped errors (<code>fmt.Errorf("...: %w", err)</code>, <code>errors.Join</code>) preserve their type and code. If
an exception is already pending, the returned error is ignored: JS receives the first exception.
<code>Env.Catch(err)</code> catches the exception signaled by <code>ErrPendingException</code> and clears it.</p>
<p><strong>IDs instead of pointers.</strong> The cgo rules forbid passing Go pointers to C. Callbacks,
values associated via <code>Wrap</code> and <code>NewExternal</code>, finalizers, and cleanup hooks are stored in two tables
(<code>callbacks</code>, <code>handles</code>) and Node-API receives an ID as <code>data</code>/<code>hint</code>. Reads are lock-free (atomic
loads on 256-slot segments); IDs are freed in the finalizer of the JS object holding them and
reused. A function created with <code>NewFunction</code> or a class from <code>DefineClass</code> keeps its callbacks
alive until V8 garbage-collects it. <code>ReadStats</code> exposes the counters (for leak tests).</p>
<p><strong>Per-env state.</strong> <code>Init</code> runs for every env that loads the addon (main thread and <code>worker_threads</code>).
The napi state for an env is stored via <code>napi_set_instance_data</code> and released when the env is
destroyed; <code>Env.SetInstanceData</code> stores the user's value within it. Therefore, an addon using napi
must not call <code>sys.SetInstanceData</code> or register <code>sys</code> handlers directly.</p>
<p><strong>Allocations.</strong> Measured in e2e tests: 0 Go allocations per call for a callback,
reading/writing numbers, <code>typeof</code>, reading a property by string key (key created
with <code>node_api_create_property_key_utf8</code> when available), and <code>Function.Call</code> with no arguments.
<code>GoString</code> reads strings up to 250 bytes into a stack buffer with a single cgo crossing:
the only allocation is the Go string. <code>Call</code> and <code>New</code> with arguments allocate the argument buffer
(functions that execute JS cannot be marked <code>nocallback</code>, so cgo moves the buffer to the heap).</p>
<p><strong>Zero-copy buffers.</strong> <code>Bytes</code>, <code>NewBuffer</code>, <code>NewArrayBuffer</code>, and <code>TypedArray.Info</code> return
a <code>[]byte</code> backed by V8 memory, valid as long as the object is alive and not detached: copy it before
retaining it or passing it to a goroutine. <code>NewExternalBuffer</code>/<code>NewExternalArrayBuffer</code> hand JS
Go memory pinned with <code>runtime.Pinner</code> until the finalizer runs; where external buffers are not
allowed (<code>napi_no_external_buffers_allowed</code>: V8 sandbox, Electron) they fall back to a copy.</p>
<h2 id="threading"><a class="heading-anchor" href="#threading">Threading</a></h2>
<p>Everything except the APIs listed below must be called on the env's JS thread, inside a callback,
<code>Init</code>, or code those run (a <code>Resolver</code>, a <code>callJS</code>, a finalizer). <code>Env</code>, <code>Value</code>, and <code>Ref</code> must
not be used from other goroutines. To work from goroutines:</p>
<table>
<thead>
<tr>
<th>API</th>
<th>Use</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>Env.Async(work)</code></td>
<td>returns a Promise settled by <code>work</code>, which runs in a goroutine without <code>Env</code> and returns a <code>Resolver</code> that builds the result on the JS thread (napi-rs <code>AsyncTask</code> / <code>async fn</code>). Errors and panics reject it; the event loop stays alive until it settles</td>
</tr>
<tr>
<td><code>Env.Context()</code></td>
<td>a <code>context.Context</code> canceled when the env is destroyed (worker terminated, process exiting): goroutines started for the env should stop</td>
</tr>
<tr>
<td><code>NewThreadsafeFunction[T](env, fn, callJS, opts)</code></td>
<td>goroutines <code>Call(v T, Blocking/NonBlocking)</code>; <code>callJS</code> converts <code>v</code> and calls <code>fn</code> on the JS thread (<code>Napi::TypedThreadSafeFunction</code>). <code>Acquire</code>/<code>Release</code>/<code>Abort</code> from any goroutine, <code>Ref</code>/<code>Unref</code> on the JS thread</td>

<td>goroutines call a JS function and receive its converted result (<code>Call(ctx, a)</code>)</td>
</tr>
</tbody>
</table>
<p>How it works and what it guarantees:</p>
<ul>
<li><strong>One dispatcher per env.</strong> Each env (main thread, worker) has one <code>napi_threadsafe_function</code>,
unref'd, and a Go queue of closures: a burst of results from goroutines costs one Node-API call
(the call is made only when the queue goes from empty to non-empty). <code>Async</code> keeps the event
loop alive while work is pending. A closure that throws ends its batch, and the remaining
closures run on the next call.</li>
<li><strong>Destroyed envs.</strong> When the env is destroyed, <code>Env.Context()</code> is canceled and pending Promises
are dropped (nobody can observe them). The methods of a <code>ThreadsafeFunction</code> then return
<code>ErrClosing</code>: calls hold a read lock that the finalizer takes for writing, so a goroutine can
never call a function Node has already freed.</li>
<li><strong>Closed functions.</strong> After the last <code>Release</code>, or after <code>Abort</code>, every method returns
<code>ErrClosing</code>. Node-API itself keeps accepting calls until the JS thread notices, and reports
<code>napi_invalid_arg</code> after an abort.</li>
<li><strong>Blocking calls.</strong> Node wakes a thread blocked on a full queue with a single
<code>cond->Signal</code>, and only when it pops from a full queue or closes the function
(<code>src/node_api.cc</code>): with several threads blocked at once, wake-ups are lost. <code>Call</code> first tries
without blocking. If the queue is full, goroutines wait for room one at a time.</li>
<li><strong>Errors in <code>callJS</code>.</strong> An error or panic in <code>callJS</code> is thrown on the JS thread. Node reports
it as an uncaught exception for modules declaring Node-API 10 (<code>napi_go_v10</code>) or with
<code>--force-node-api-uncaught-exceptions-policy=true</code>. Otherwise it emits the DEP0168 warning and
drops it.</li>
</ul>
<h2 id="current-limitations"><a class="heading-anchor" href="#current-limitations">Current limitations</a></h2>
<ul>
<li>With <code>napi_go_experimental</code>, finalizers may run inside V8's GC: <code>FinalizeFunc</code> callbacks
must not call functions that execute JS (<code>node_api_post_finalizer</code> is not exposed yet).</li>
<li><code>DefineClass</code> creates base classes: inheriting from a native class works from JS
(<code>class Sub extends Counter</code>), not between classes defined in Go.</li>
<li>Async context, <code>MakeCallback</code> and <code>napi_async_work</code> (the libuv thread pool) are available only in
<code>sys</code>; <code>Env.Async</code> runs work in goroutines.</li>
<li>A <code>ThreadsafeFunction</code> call does not return the JS result: use <code>JSFunc</code> for that.</li>
<li>Layer 2: no async methods (use <code>Env.Async</code> in a method), no variadic Go functions (inject
<code>CallContext</code>), class methods have <code>length</code> 0, classes defined in Go cannot extend each other,
and a <code>*T</code> converts to the class registered for <code>T</code> only (one class per Go type).</li>
<li>A class defined with <code>DefineClass</code> always throws a TypeError when called without <code>new</code>; there
is no hook to make it act as a factory (node-addon-api's <code>ObjectWrap::OnCalledAsFunction</code>).</li>
<li><code>NewSymbol</code> always sets a description: <code>Symbol()</code> without one has no counterpart.</li>
<li>SharedArrayBuffer creation (experimental Node-API) is not wrapped.</li>

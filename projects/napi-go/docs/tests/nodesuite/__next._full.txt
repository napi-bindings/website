<p>Runner rules, modeled after Node.js's <code>test/testpy</code>:</p>
<ul>
<li>each <code>.js</code> file in a test directory is a test (id <code>suite/dir/file</code>, without extension);</li>
<li>a test passes if the process exits with code 0; <code>1..0 # Skipped</code> on stdout counts it as skipped;</li>
<li>for each target in <code>binding.gyp</code>, the Go source lives in <code>&#x3C;dir>/&#x3C;target>/</code>, or directly in <code>&#x3C;dir>/</code>
when there is only one target; the addon is written to <code>build/Release/&#x3C;target>.node</code>;</li>
<li>when multiple targets compile the same C source (e.g. with different defines), the port lives in
<code>&#x3C;dir>/internal/&#x3C;name>/</code> and each <code>&#x3C;target>/main.go</code> only registers its <code>Init</code>; <code>#if NAPI_VERSION</code>
differences branch on <code>sys.DeclaredVersion</code>;</li>
<li>target defines select the <code>sys</code> build tag: none → Node-API 8, <code>NAPI_VERSION=9</code> → <code>napi_go_v9</code>,
<code>NAPI_VERSION=10</code> → <code>napi_go_v10</code>, <code>NAPI_EXPERIMENTAL</code> → <code>napi_go_experimental</code>,
<code>NAPI_VERSION=2147483646</code> → <code>napi_go_test_version_mismatch</code> (only <code>test_module_version_mismatch</code>);</li>
<li>a test exceeding 120 s is killed along with all child processes (process group on POSIX,
<code>taskkill /T</code> on Windows) and the report includes <code>ps</code> output and, on macOS, thread stack traces
(<code>sample</code>);</li>
<li>scripts run with <code>UV_THREADPOOL_SIZE</code> and <code>NODE_OPTIONS</code> stripped from the runner environment,
matching Node.js CI (an <code>// Env:</code> line can set them again); <code>tmpdir</code> uses
<code>tests/nodesuite/.tmp.0</code>.</li>
</ul>

<h2 id="unavoidable-differences-from-c"><a class="heading-anchor" href="#unavoidable-differences-from-c">Unavoidable Differences from C</a></h2>
<ul>
<li>The <code>data</code> of JS functions created from Go carries the index of the function registered in
<code>napitest</code> (<code>sys.CallbackTrampoline</code> dispatch), not the C test's <code>data</code>.</li>
<li>Names passed to property descriptors are shared, never-freed C strings (<code>nt.CStr</code>, <code>nt.UTF16</code>),
so descriptors contain no Go pointers.</li>
<li>An accessor's getter and setter share <code>data</code> (as in Node-API): <code>nt.Accessor</code> registers the pair
and dispatch selects the getter for a zero-argument call and the setter for a one-argument call.
Registry index 0 is reserved so a NULL <code>data</code> never invokes a function.</li>
<li>Functions created repeatedly (factories) are registered once at package level: each <code>nt.Register</code>
appends an entry to the registry.</li>
<li>C++ classes become Go structs and the native pointer passed to <code>napi_wrap</code> / <code>napi_add_finalizer</code>
is a <code>cgo.Handle</code>. Structs that C allocates with <code>malloc</code> and passes as instance data or
<code>finalize_data</code> (containing only C types such as <code>napi_ref</code>) stay in C memory (<code>nt.Malloc</code>).
A finalizer canceled by deleting its reference (<code>6_object_wrap/nested_wrap</code>) is never called and
its <code>nt.Finalizer</code> handle remains allocated, just like the memory in the C test.</li>
<li>A TSFN context is a <code>napitest</code> token and is never released: Node-API calls <code>call_js_cb</code> with a
NULL env for items remaining in the queue even after <code>thread_finalize_cb</code> and does not signal when
it is done. <code>thread_finalize_cb</code> receives the original context as its hint.</li>
<li>Finalizers go through <code>sys.FinalizeTrampoline</code>: <code>nt.Finalizer(fn, hint)</code> returns the callback/hint
pair to pass instead of the C pair, and <code>fn</code> receives Node-API's <code>finalize_data</code> and the original
hint. Memory that Node-API must be able to access after the call returns (external strings and
ArrayBuffers) is allocated with <code>nt.Malloc</code> and freed with <code>nt.Free</code> / <code>nt.FreeAddr</code>. <code>nt.Malloc</code>
never returns NULL for a non-zero size: if allocation fails it aborts the process with a message,
because the C tests use the result of <code>malloc</code> without checking it.</li>
</ul>

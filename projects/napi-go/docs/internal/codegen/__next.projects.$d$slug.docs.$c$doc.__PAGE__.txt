<h2 id="annotations"><a class="heading-anchor" href="#annotations">Annotations</a></h2>
<p>Annotations are written like Go directives, with no space after <code>//</code>, in the doc comment of the
declaration. An unknown or misplaced annotation is an error.</p>
<table>
<thead>
<tr>
<th>Annotation</th>
<th>On</th>
<th>Effect</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>//napi:export [name]</code></td>
<td>function</td>
<td>exported function; <code>name</code> defaults to the Go name in lowerCamelCase. A first parameter of type <code>context.Context</code> makes it asynchronous (it runs in a goroutine and returns a Promise)</td>
</tr>
<tr>
<td><code>//napi:export Class.name</code></td>
<td>function, constant</td>
<td>static method or static constant of a class</td>
</tr>
<tr>
<td><code>//napi:export [name]</code></td>
<td>constant, variable</td>
<td>exported constant (the value when the addon is loaded)</td>
</tr>
<tr>
<td><code>//napi:class [Name]</code></td>
<td>type</td>
<td>JS class whose instances wrap a <code>*T</code>. Every exported method of <code>*T</code> becomes a method, except <code>Finalize</code>, <code>FromJS</code>, <code>ToJS</code> and those marked <code>//napi:skip</code></td>
</tr>
<tr>
<td><code>//napi:constructor</code></td>
<td>function returning <code>(*T, error)</code></td>
<td>constructor of the class of <code>T</code>. Without one the class cannot be constructed from JS</td>
</tr>
<tr>
<td><code>//napi:export name</code></td>
<td>method</td>
<td>renames the method</td>
</tr>
<tr>
<td><code>//napi:getter [name]</code></td>
<td>method <code>func (*T) X() V</code></td>
<td>property getter (<code>V, error</code> allowed)</td>
</tr>
<tr>
<td><code>//napi:setter [name]</code></td>
<td>method <code>func (*T) SetX(v V)</code></td>
<td>setter of the property with the same name; the default name drops the <code>Set</code> prefix</td>
</tr>
<tr>
<td><code>//napi:skip</code></td>
<td>method</td>
<td>not exported</td>
</tr>
<tr>
<td><code>//napi:object [Name]</code></td>
<td>struct type</td>
<td>emits its interface even if no export uses it, optionally renamed. Structs used by an export are emitted without it</td>
</tr>
<tr>
<td><code>//napi:type &#x3C;TypeScript type></code></td>
<td>type</td>
<td>TypeScript type of a type that converts itself (<code>FromJS</code>/<code>ToJS</code>), <code>any</code> otherwise</td>
</tr>
<tr>
<td><code>//napi:returns &#x3C;TypeScript type></code></td>
<td>function, method</td>
<td>overrides the declared return type (e.g. <code>this</code>, or <code>Promise&#x3C;string[]></code> for a function returning a <code>napi.Promise</code>)</td>
</tr>
</tbody>
</table>
<p>Functions take up to 8 parameters and return nothing, a value, an error, or a value and an error;
asynchronous functions return <code>(R, error)</code> or <code>error</code>. Parameters of type <code>napi.Env</code> and
<code>napi.CallContext</code> are filled by napi and do not appear in the declarations (<code>CallContext</code> adds
<code>...args: any[]</code>). Variadic and generic functions, asynchronous methods and classes used by value
(<code>T</code> instead of <code>*T</code>) are rejected with an explanation.</p>

<h2 id="usage"><a class="heading-anchor" href="#usage">Usage</a></h2>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>napi-go gen [flags]</span></span>
<span class="line"><span></span></span>
<span class="line"><span>  -C dir             project (package.json) or Go package directory (default .)</span></span>
<span class="line"><span>  -name name         base name of the .node files (default: binaryName of package.json, or the directory name)</span></span>
<span class="line"><span>  -package-name pkg  npm package of the platform packages (default: name of package.json)</span></span>
<span class="line"><span>  -js file           JS entry point (default index.js; empty: none)</span></span>
<span class="line"><span>  -dts file          TypeScript declarations (default index.d.ts; empty: none)</span></span>
<span class="line"><span>  -tags tags         build tags, as for go build</span></span>
<span class="line"><span>  -check             do not write: fail if the generated files are out of date (for CI)</span></span></code></pre>
<p>In a project, the files go next to <code>package.json</code> and <code>zz_napi.go</code> into the Go package
(<code>napiGo.goPackage</code>); <code>go generate</code> in the Go package finds the <code>package.json</code> above it.</p>
<p>The generator uses only the Go standard library. It type-checks the package with the export data
of the Go build cache (<code>go list -export</code>), so it needs the same toolchain as the build, C compiler
included.</p>
<h2 id="what-is-generated-and-what-is-not"><a class="heading-anchor" href="#what-is-generated-and-what-is-not">What is generated, and what is not</a></h2>
<p>The generated Go code registers the exports with the generic wrappers of package <code>napi</code>; the
conversions are the cached codecs of Layer 2. Generating Go conversion code for each struct was
measured and dropped: on a struct of five fields it was 15% faster from JS to Go and no faster from
Go to JS (about 2 µs either way), because the time goes into the Node-API calls for each property,
not into Go.

<h2 id="reading-the-results"><a class="heading-anchor" href="#reading-the-results">Reading the results</a></h2>
<ul>
<li><strong>The floor of a call is the cgo callback, about 100 ns.</strong> Node.js calls the addon on its own
thread, which is not a Go thread: entering Go from C costs about 100 ns (<code>runtime.cgocallback</code>),
against a direct function call for Rust and C++. Every napi-go function pays it once; the
conversions of numbers, booleans and short strings then run in C in the same crossing (the typed
trampoline, <code>sys/typed.c</code>), which is why <code>add</code> costs only 34 ns more than <code>noop</code>.</li>
<li><strong>Short strings are close to napi-rs; long ones are about twice as slow.</strong> Up to about 500 bytes
a string is read in C in the same crossing. A longer one falls back to Go
(<code>Value.GoString</code>): a first read into a 256-byte buffer, a query of the length and a second read,
each one a cgo crossing in which V8 scans the whole string. napi-rs and node-addon-api query the
length and read once.</li>
<li><strong><code>[]byte</code> parameters are not handled by the typed trampoline</strong>: reading a Buffer takes two more
crossings from Go (<code>napi_is_typedarray</code>, <code>napi_get_typedarray_info</code>), about 220 ns. The data is
not copied: the cost does not depend on the size.</li>
<li><strong>A returned <code>[]byte</code> is copied.</strong> <code>makeBuffer</code> allocates and clears 1 MiB on the Go heap, then
Node-API copies it into a new Buffer (<code>napi_create_buffer_copy</code>); with allocations of this size
the Go garbage collector runs about every third call (332 cycles in 1,000 calls with
<code>GODEBUG=gctrace=1</code>). napi-rs hands its <code>Vec</code> to V8 without copying
(external buffer). In napi-go, <code>Env.NewBuffer</code> (Layer 1) creates the Buffer in V8 memory and
returns a <code>[]byte</code> view to fill, without the copy.</li>
<li><strong>Promises in bulk are 3–6 times faster than napi-rs and node-addon-api.</strong> napi-go settles
Promises through one threadsafe function per env with a Go queue, and wakes the JS thread only
when the queue becomes non-empty: a thousand goroutines finishing together cost one wake-up.
napi-rs and node-addon-api pay one per Promise. The latency of a single Promise is higher
(a goroutine wakes up, then the JS thread).</li>
</ul>

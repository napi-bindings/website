19:T117b,<h1 id="releasing-napi-go">Releasing napi-go</h1>
<p>napi-go is a Go module: a release is a git tag <code>v&#x3C;major>.&#x3C;minor>.&#x3C;patch></code>. Users get it with
<code>go get github.com/napi-bindings/napi-go@&#x3C;tag></code> and run the CLI of the same version with
<code>go tool napi-go</code> (or <code>go run github.com/napi-bindings/napi-go/cmd/napi-go@&#x3C;tag></code>).</p>
<h2 id="checklist"><a class="heading-anchor" href="#checklist">Checklist</a></h2>
<ol>
<li>
<p><strong><code>main</code> is green</strong>: the workflows <code>sys</code>, <code>cli</code> and <code>bench</code> on the commit to release.</p>
</li>
<li>
<p><strong>CHANGELOG.md</strong>: the section of the version lists the changes and has the date of the release,
<code>## [0.1.0] - 2026-11-20</code> (the release workflow refuses a section without a date).</p>
</li>
<li>
<p><strong>Commit</strong> the changelog to <code>main</code>, then <strong>tag</strong> that commit and push the tag:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">git</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> tag</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -a</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> v0.1.0</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -m</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> "napi-go 0.1.0"</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">git</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> push</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> origin</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> v0.1.0</span></span></code></pre>
</li>
<li>
<p><strong>The release workflow</strong> (<a href="https://github.com/napi-bindings/napi-go/blob/main/.github/workflows/release.yml" target="_blank" rel="noreferrer noopener"><code>release.yml</code></a>) then:</p>
<ul>
<li>checks the tag against CHANGELOG.md and extracts the release notes;</li>
<li>builds the CLI for Linux, macOS and Windows (x64 and arm64), with <code>SHA256SUMS</code>, and checks
that it reports the tag as its version;</li>
<li>on Linux, macOS and Windows, creates a project with
<code>go run github.com/napi-bindings/napi-go/cmd/napi-go@&#x3C;tag> new</code>, fetching the tag from
GitHub as a user would, then builds and tests it;</li>
<li>creates the GitHub release with the notes and the binaries (a pre-release for tags such as
<code>v0.2.0-rc.1</code>).</li>
</ul>
</li>
<li>
<p><strong>Make the version known to the Go proxy and pkg.go.dev</strong>:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">GOPROXY</span><span style="color:#D73A49;--shiki-dark:#F97583">=</span><span style="color:#032F62;--shiki-dark:#9ECBFF">https://proxy.golang.org</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> go</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> list</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -m</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> github.com/napi-bindings/napi-go@v0.1.0</span></span></code></pre>
<p>then open <code>https://pkg.go.dev/github.com/napi-bindings/napi-go@v0.1.0</code> (the page appears within
minutes, or request it there).</p>
</li>
<li>
<p><strong>Start the next section</strong> of CHANGELOG.md: <code>## [Unreleased]</code>.</p>
</li>
</ol>
<p>If the release workflow fails, fix the cause on <code>main</code> and release a new patch version: a tag
published to the Go proxy cannot be changed. Until the proxy has fetched it, a wrong tag can still
be deleted (<code>git push origin :refs/tags/v0.1.0</code>) and created again.</p>
<h2 id="versions"><a class="heading-anchor" href="#versions">Versions</a></h2>
<ul>
<li>Before 1.0.0 a minor version may change the API; CHANGELOG.md lists the changes.</li>
<li>napi-go supports the two latest Go releases (with cgo) and the Node.js versions tested in CI
(currently 22, 24 and 26). Addons declare Node-API 8 unless built with <code>napi_go_v9</code> or
<code>napi_go_v10</code>.</li>
<li>The CLI and the library share the module version: projects pin both with <code>go.mod</code>.</li>

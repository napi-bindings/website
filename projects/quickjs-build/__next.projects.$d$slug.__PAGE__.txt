<h2 id="introduction"><a class="heading-anchor" href="#introduction">Introduction</a></h2>
<p><strong>QuickJS</strong> is a small and embeddable JavaScript engine. It supports most of the
<strong><a href="https://tc39.es/ecma262/" target="_blank" rel="noreferrer noopener">ES2025</a></strong> specification including modules,
asynchronous generators, proxies and BigInt.</p>
<h3 id="main-features"><a class="heading-anchor" href="#main-features">Main Features:</a></h3>
<ul>
<li>Small and easily embeddable: just a few <strong>C</strong> files, no external dependency,
<strong>210 KiB</strong> of x86 code for a simple hello world program.</li>
<li>Fast interpreter with very low startup time: runs the tests of the
<strong><a href="https://github.com/tc39/test262" target="_blank" rel="noreferrer noopener">ECMAScript Test Suite</a></strong> in less than 2
minutes on a single core of a desktop PC. The complete life cycle of a runtime
instance completes in less than 300 microseconds.</li>
<li>Almost complete <strong>ES2025</strong> support.</li>
<li>Passes nearly 100% of the
<strong><a href="https://github.com/tc39/test262" target="_blank" rel="noreferrer noopener">ECMAScript Test Suite</a></strong> tests when selecting
the ES2025 features.</li>
<li>Can compile JavaScript sources to executables with no external dependency.</li>
<li>Garbage collection using reference counting (to reduce memory usage and have
deterministic behavior) with cycle removal.</li>
<li>Command line interpreter with contextual colorization implemented in JavaScript.</li>
<li>Small built-in standard library with <strong>C</strong> library wrappers.</li>
</ul>
<p>This repository is a mirror of the original work that you can find
<strong><a href="https://bellard.org/quickjs/" target="_blank" rel="noreferrer noopener">here</a></strong>. The files in <code>src/</code>, <code>include/</code> and
<code>tests/</code> are the unmodified files of the <code>quickjs-2026-06-04</code> release.</p>
<p>The mathematical extensions of the previous releases (BigFloat, BigDecimal,
operator overloading) were removed upstream and are no longer available. See the
<a href="/projects/quickjs-build/changelog/">changelog</a> for the list of the API changes.</p>

<h2 id="using-the-library"><a class="heading-anchor" href="#using-the-library">Using the library</a></h2>
<p>Compile and link your program against the content of the archive:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>cc -Iinclude my_program.c libqjs.a -lm -lpthread -ldl -o my_program</span></span></code></pre>
<p><code>-ldl</code> is not needed on Windows, macOS and FreeBSD. On Windows add <code>-static</code> to
avoid the dependency on <code>libwinpthread-1.dll</code>.</p>
<p><a href="https://github.com/napi-bindings/quickjs-build/blob/master/smoke/embed.c" target="_blank" rel="noreferrer noopener"><code>smoke/embed.c</code></a> is a complete example that creates a runtime,
evaluates a script and reads the result back. The CI builds it for every target
and runs it wherever the binaries can be executed.</p>

<h2 id="using-the-webassembly-builds"><a class="heading-anchor" href="#using-the-webassembly-builds">Using the WebAssembly builds</a></h2>
<p>Both WebAssembly archives contain the engine only: <code>quickjs-libc</code> needs
processes, pipes and signals that are not available there. Your program provides
what it needs (for example a <code>print</code> function) through the QuickJS C API.</p>
<h3 id="wasi"><a class="heading-anchor" href="#wasi">WASI</a></h3>
<p>Link <code>libqjs.a</code> with a WASI toolchain such as <code>zig cc -target wasm32-wasi</code> or
<a href="https://github.com/WebAssembly/wasi-sdk" target="_blank" rel="noreferrer noopener">wasi-sdk</a>:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>zig cc -target wasm32-wasi -O2 -Iinclude my_program.c libqjs.a \</span></span>
<span class="line"><span>  -Wl,-z,stack-size=1048576 -o my_program.wasm</span></span></code></pre>
<p>The resulting module runs on any WASI runtime, for example
<a href="https://wasmtime.dev/" target="_blank" rel="noreferrer noopener">Wasmtime</a> or Node.js (see
<a href="https://github.com/napi-bindings/quickjs-build/blob/master/smoke/run-wasi.mjs" target="_blank" rel="noreferrer noopener"><code>smoke/run-wasi.mjs</code></a>).</p>
<p><strong>Set the stack limit of the runtime.</strong> The WebAssembly call stack belongs to the
host and is invisible to the engine, which only measures the stack kept in the
linear memory. With the default limit of QuickJS (1 MiB) a runaway recursion
exhausts the call stack of the host first and the module traps instead of
throwing a JavaScript <code>InternalError</code>. Lower the limit right after creating the
runtime and give the module a linear memory stack larger than that limit:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">JSRuntime </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#24292E;--shiki-dark:#E1E4E8">rt </span><span style="color:#D73A49;--shiki-dark:#F97583">=</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> JS_NewRuntime</span><span style="color:#24292E;--shiki-dark:#E1E4E8">();</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">JS_SetMaxStackSize</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(rt, </span><span style="color:#005CC5;--shiki-dark:#79B8FF">256</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> 1024</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>With these values the recursion test of <code>smoke/embed.c</code> ends with a catchable
exception on Node.js 22. Other hosts may need a different value.</p>
<h3 id="emscripten"><a class="heading-anchor" href="#emscripten">Emscripten</a></h3>
<p>Link <code>libqjs.a</code> with <code>emcc</code>:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>emcc -O2 -Iinclude my_program.c libqjs.a -o my_program.js</span></span></code></pre>
<p>When built with Emscripten the engine disables <code>Atomics</code> and its own stack
check, so a runaway recursion ends with the <code>RangeError</code> of the host.</p>
<h2 id="building"><a class="heading-anchor" href="#building">Building</a></h2>
<p>If you want to build the QuickJS library on your own the first step is to clone
this repository:</p>
<p><code>> git clone https://github.com/napi-bindings/quickjs-build.git</code></p>
<p>You need <strong>CMake</strong> 3.20 or later and <strong>GCC</strong> or <strong>Clang</strong>.</p>
<h3 id="native-build"><a class="heading-anchor" href="#native-build">Native build</a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>cmake -S . -B build -DCMAKE_BUILD_TYPE=Release</span></span>
<span class="line"><span>cmake --build build</span></span>
<span class="line"><span>cmake --build build --target check</span></span></code></pre>
<p>The last command runs the QuickJS tests stored in <code>tests/</code>.</p>
<p>On <strong>Windows</strong> install a MinGW-w64 toolchain (for example with
<a href="https://www.msys2.org/" target="_blank" rel="noreferrer noopener">MSYS2</a>), be sure that <code>gcc</code> is in your path of execution
and add <code>-G "MinGW Makefiles"</code> to the first command.</p>
<p>On <strong>Linux</strong> install the dependencies with:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>sudo apt-get update</span></span>
<span class="line"><span>sudo apt-get install build-essential cmake -y</span></span></code></pre>
<p>On <strong>macOS</strong> install the <code>Xcode Command Line Tools</code> running
<code>xcode-select --install</code> and CMake running <code>brew install cmake</code>.</p>
<p><code>-DCMAKE_BUILD_TYPE</code> could be set with one of the following two values:</p>
<ul>
<li>Release</li>
<li>Debug</li>
</ul>

<h3 id="cross-compiling-with-zig"><a class="heading-anchor" href="#cross-compiling-with-zig">Cross-compiling with zig</a></h3>
<p><a href="https://github.com/napi-bindings/quickjs-build/blob/master/toolchains/zig.cmake" target="_blank" rel="noreferrer noopener"><code>toolchains/zig.cmake</code></a> is a CMake toolchain file that
uses <code>zig cc</code> as the C compiler. With it one machine builds the library for all
the platforms of the table above, with no other cross-compiler or SDK. The CI
uses zig 0.17.1; the build also works with zig 0.16.0.</p>
<p>The script <a href="https://github.com/napi-bindings/quickjs-build/blob/master/scripts/build.sh" target="_blank" rel="noreferrer noopener"><code>scripts/build.sh</code></a> runs the whole process and
writes the archives to <code>dist/</code>. It needs a POSIX shell (Linux, macOS, WSL):</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>sh scripts/build.sh --list</span></span>
<span class="line"><span>sh scripts/build.sh linux-arm64 windows-x86_64</span></span>
<span class="line"><span>sh scripts/build.sh --test linux-x86_64</span></span>
<span class="line"><span>sh scripts/build.sh all</span></span></code></pre>
<p>The build has two stages, because the <code>quickjs</code> executable embeds the bytecode of
<code>repl.js</code> generated by <code>qjsc</code>, and a cross-compiled <code>qjsc</code> cannot run on the
build machine:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span># 1. qjsc for the build machine</span></span>
<span class="line"><span>cmake -S . -B build/host -DCMAKE_BUILD_TYPE=Release</span></span>
<span class="line"><span>cmake --build build/host --target qjsc</span></span>
<span class="line"><span></span></span>
<span class="line"><span># 2. the target</span></span>
<span class="line"><span>cmake -S . -B build/linux-arm64 -DCMAKE_BUILD_TYPE=Release \</span></span>
<span class="line"><span>  -DCMAKE_TOOLCHAIN_FILE=toolchains/zig.cmake \</span></span>
<span class="line"><span>  -DZIG_TARGET=aarch64-linux-gnu.2.17 \</span></span>
<span class="line"><span>  -DQJSC_EXECUTABLE=$PWD/build/host/qjsc</span></span>
<span class="line"><span>cmake --build build/linux-arm64</span></span></code></pre>
<p><code>ZIG_TARGET</code> is a zig target triple; the suffix after the ABI selects the minimum
glibc version and the suffix after <code>macos</code> the minimum macOS version. Set
<code>CMAKE_CROSSCOMPILING_EMULATOR</code> to run the tests of a foreign architecture, for
example <code>-DCMAKE_CROSSCOMPILING_EMULATOR="qemu-aarch64;-L;/usr/aarch64-linux-gnu"</code>.</p>
<p>The WebAssembly targets have no tools and skip the first stage:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span>sh scripts/build.sh --test wasm32-wasi</span></span>
<span class="line"><span>sh scripts/build.sh --test wasm32-emscripten</span></span></code></pre>
<p>The second command needs the <a href="https://emscripten.org/" target="_blank" rel="noreferrer noopener">Emscripten SDK</a> with
<code>emcmake</code> in your path of execution, instead of zig.</p>
<h2 id="updating-quickjs"><a class="heading-anchor" href="#updating-quickjs">Updating QuickJS</a></h2>
<p>The QuickJS files are copied without changes from the upstream tarball:</p>
<ul>
<li><code>src/</code>: the <code>.c</code>, <code>.h</code> and <code>repl.js</code> files needed by the library and the tools;</li>
<li><code>include/</code>: <code>quickjs.h</code> and <code>quickjs-libc.h</code>;</li>
<li><code>tests/</code>: the test scripts run by the <code>check</code> target;</li>
<li><code>VERSION</code> and <code>LICENSE.quickjs</code> (the upstream <code>LICENSE</code>).</li>
</ul>
<p>To update, replace these files with the ones of the new release, review the
source list in <code>CMakeLists.txt</code> against the upstream <code>Makefile</code> and run the
tests.</p>

<h2 id="2026-11-15-version-700-nicknaso"><a class="heading-anchor" href="#2026-11-15-version-700-nicknaso">2026-11-15 Version 7.0.0, @NickNaso</a></h2>
<h3 id="notable-changes"><a class="heading-anchor" href="#notable-changes">Notable changes</a></h3>
<ul>
<li>Update QuickJS to version 2026-06-04. The engine now supports most of ES2025:
top-level await, WeakRef and FinalizationRegistry, iterator helpers, the Set
methods, resizable ArrayBuffer, the RegExp <code>v</code> flag and modifiers,
Float16Array, JSON modules with import attributes, <code>Promise.try</code>,
<code>Math.sumPrecise</code> and more.</li>
<li>The release archives are cross-compiled with <code>zig cc</code> from one Linux runner:
13 native platforms instead of 5, plus WebAssembly (<code>wasm32-wasi</code> and
<code>wasm32-emscripten</code>, engine only).</li>
<li>New <code>qjs-windows-x86_64-mingw.zip</code> and <code>qjs-windows-x86-mingw.zip</code> archives,
built natively on Windows with MinGW-w64 11 (MinGW-Builds GCC 13.2, msvcrt):
they link with MinGW-w64 toolchains that cannot link the zig archives,
including releases older than 12.</li>
<li>The Linux archives no longer depend on the Ubuntu version of the CI runner:
they need glibc 2.17 or later (2.27 for RISC-V). Static musl builds are also
provided.</li>
<li>New CMake options <code>QJS_BUILD_LIBC</code>, <code>QJS_BUILD_TOOLS</code>, <code>QJS_BUILD_SMOKE_TEST</code>
and <code>QJSC_EXECUTABLE</code>; new <code>check</code> target that runs the QuickJS tests.</li>
<li>New CMake toolchain file <code>toolchains/zig.cmake</code> and build script
<code>scripts/build.sh</code>. <code>toolchains/linux_aarch64.cmake</code> and the dependency on
qemu to build for arm64 were removed.</li>
<li>The CI runs the tests on Linux x86_64, x86, arm64, armv7 and riscv64 and on
real Windows and macOS runners, and publishes a <code>SHA256SUMS</code> file with every
release.</li>
</ul>
<h3 id="breaking-changes"><a class="heading-anchor" href="#breaking-changes">Breaking changes</a></h3>
<h4 id="quickjs-api"><a class="heading-anchor" href="#quickjs-api">QuickJS API</a></h4>
<ul>
<li>The mathematical extensions were removed upstream: <code>CONFIG_BIGNUM</code>,
<code>libbf</code>, <code>qjscalc</code>, BigFloat, BigDecimal and operator overloading are gone,
together with <code>JS_AddIntrinsicBigFloat</code>, <code>JS_AddIntrinsicBigDecimal</code>,
<code>JS_AddIntrinsicOperators</code>, <code>JS_EnableBignumExt</code>, <code>JS_IsBigFloat</code> and
<code>JS_IsBigDecimal</code>. BigInt is always available and <code>JS_AddIntrinsicBigInt</code>
no longer exists.</li>
<li><code>JS_EVAL_FLAG_STRIP</code> was removed: use <code>JS_SetStripInfo</code>.</li>
<li><code>JS_ResetUncatchableError</code> was removed: use <code>JS_SetUncatchableException</code>.</li>
<li><code>JS_RunModule</code> was removed: use <code>JS_LoadModule</code>.</li>
<li><code>JS_PROP_NO_ADD</code>, <code>JS_VALUE_GET_OBJ</code> and <code>JS_VALUE_GET_STRING</code> were removed
from <code>quickjs.h</code>.</li>
<li><code>JS_SetPropertyInternal</code> has an additional <code>this_obj</code> parameter.</li>
<li><code>js_module_loader</code> (<code>quickjs-libc.h</code>) has an additional
<code>JSValueConst attributes</code> parameter.</li>
<li>The <code>JS_AddIntrinsic*</code> functions, <code>JS_SetConstructor</code> and
<code>JS_SetPropertyFunctionList</code> now return <code>int</code> instead of <code>void</code>.</li>
</ul>

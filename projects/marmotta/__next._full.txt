<p>Marmotta builds Node.js native addons written in C or C++ with <a href="https://nodejs.org/api/n-api.html" target="_blank" rel="noreferrer noopener">Node-API</a>. It uses <a href="https://ziglang.org/" target="_blank" rel="noreferrer noopener">Zig</a> as the compiler toolchain and can install Zig for you, so projects do not need to configure <code>node-gyp</code> or CMake.</p>

<h2 id="highlights"><a class="heading-anchor" href="#highlights">Highlights</a></h2>
<ul>
<li>Build C and C++ Node-API addons into <code>.node</code> files.</li>
<li>Use the Node-API headers supplied by Marmotta; no separate Node header installation is needed.</li>
<li>Reuse node-gyp-oriented sources that use <code>NODE_GYP_MODULE_NAME</code>.</li>
<li>Build for the host platform or pass a Zig target triple for cross-compilation.</li>
<li>Install Zig automatically when a suitable compiler is not already on <code>PATH</code>.</li>
<li>Use a Zig installation that already exists on the system with <code>MARMOTTA_ZIG_DIR</code>, for example where downloads are blocked.</li>
<li>Load the same addon in Node.js, Electron, Deno, and Bun. On Windows, Marmotta binds Node-API functions to the process that loads the addon instead of to <code>node.exe</code>, so no delay-load hook is needed.</li>
</ul>
<h2 id="requirements"><a class="heading-anchor" href="#requirements">Requirements</a></h2>
<ul>
<li>Node.js 20 or later and npm. To run Marmotta without Node.js, use a <a href="#standalone-binary">standalone binary</a> instead.</li>
<li>A C or C++ Node-API addon source file (<code>.c</code>, <code>.cc</code>, <code>.cpp</code>, or <code>.cxx</code>).</li>
<li><code>tar</code> and internet access when Marmotta needs to download Zig.</li>
</ul>
<p>Automatic Zig downloads are supported on x64 and ARM64 Linux, macOS, and Windows hosts. On other host platforms, install Zig separately and make it available on <code>PATH</code>.</p>

<p>Each release includes a <code>SHA256SUMS</code> file and GitHub build provenance attestations, so
a download can be checked with <code>sha256sum --check --ignore-missing SHA256SUMS</code> and
<code>gh attestation verify</code>.</p>
<p>Notes on the standalone binaries:</p>
<ul>
<li>They behave like the npm package: <code>NODE_OPTIONS</code> does not affect them, and a stray
<code>.env</code> or <code>bunfig.toml</code> in the project directory does not change what they do.
Like any Bun program, they do honor <code>BUN_OPTIONS</code>.</li>
<li>The macOS binaries carry an ad-hoc signature with the hardened runtime enabled and
the JIT entitlements JavaScriptCore needs; they are not notarized. If macOS blocks a
downloaded binary, remove the quarantine attribute with
<code>xattr -d com.apple.quarantine &#x3C;file></code> (or control-click and open it).</li>
<li>The musl binaries link against <code>libstdc++</code>, which a stock Alpine image does not ship.
Install it first: <code>apk add libstdc++</code>.</li>
<li>The binaries are built with <a href="https://bun.com/docs/bundler/executables" target="_blank" rel="noreferrer noopener"><code>bun build --compile</code></a>.</li>
</ul>

<h2 id="configuration"><a class="heading-anchor" href="#configuration">Configuration</a></h2>

<h3 id="logging"><a class="heading-anchor" href="#logging">Logging</a></h3>
<p>By default Marmotta writes plain text: command results on stdout and errors on stderr, with no level prefixes, so scripts that read <code>marmotta --version</code> or <code>marmotta list</code> keep working unchanged.</p>
<p>Pass <code>--json</code> when another process needs to consume the output, as in CI. The flag is recognized before or after the command, and each record is one JSON object on its own line (JSON Lines):</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> build</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --json</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --json</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> list</span></span></code></pre>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">{</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"level"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#032F62;--shiki-dark:#9ECBFF">"info"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"time"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#005CC5;--shiki-dark:#79B8FF">1730000000000</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"message"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#032F62;--shiki-dark:#9ECBFF">"Addon built: /project/build/hello.node"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">}</span></span>

<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">{</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"level"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#032F62;--shiki-dark:#9ECBFF">"error"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"time"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#005CC5;--shiki-dark:#79B8FF">1730000000002</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"data"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:{</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"code"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#032F62;--shiki-dark:#9ECBFF">"CLI_ARGUMENT_ERROR"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"exitCode"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#005CC5;--shiki-dark:#79B8FF">2</span><span style="color:#24292E;--shiki-dark:#E1E4E8">},</span><span style="color:#005CC5;--shiki-dark:#79B8FF">"message"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">:</span><span style="color:#032F62;--shiki-dark:#9ECBFF">"Unknown option: --bogus"</span><span style="color:#24292E;--shiki-dark:#E1E4E8">}</span></span></code></pre>
<ul>
<li><code>level</code> is a string such as <code>info</code>, <code>warn</code>, or <code>error</code>. Informational records go to stdout; warnings and errors go to stderr.</li>
<li><code>message</code> is the human-readable text, and <code>data</code> carries the record's structured context when there is any, such as the error <code>code</code> and <code>exitCode</code>, the installed <code>versions</code>, or a child process's <code>command</code> and <code>stream</code>.</li>
<li>Command results, such as help, the version, <code>list</code>, confirmations and error messages, are always printed. Output from the Zig and <code>tar</code> child processes is captured and re-emitted as records tagged with <code>command</code> and <code>stream</code>, so every line printed in <code>--json</code> mode is valid JSON and compiler errors are never hidden. Lines from the child's stderr are <code>warn</code> records on stderr; lines from its stdout are <code>info</code> records on stdout. Lines keep their order within each stream, but the order between a child's stdout and stderr lines is not preserved.</li>
<li>Set <code>MARMOTTA_LOG</code> to the minimum level for diagnostic records: <code>trace</code>, <code>debug</code>, <code>info</code>, <code>warn</code>, <code>error</code>, <code>fatal</code>, or <code>silent</code>. The default is <code>info</code>, which hides <code>debug</code> records: which Zig is used, where Zig is downloaded from, and each Zig or <code>tar</code> command line. An unrecognized value is ignored with a warning.</li>
</ul>
<p><code>MARMOTTA_LOG</code> filters diagnostics only; it never hides a command's result or its final error. It applies to both formats and does not change the shape of the output.</p>
<p><code>--version</code> is a top-level request and cannot be combined with a command, so <code>marmotta build --version</code> fails with an argument error instead of printing the version and skipping the build.</p>
<h2 id="zig-toolchain"><a class="heading-anchor" href="#zig-toolchain">Zig toolchain</a></h2>
<p>Without a <code>zigVersion</code> pin, Marmotta uses <code>zig</code> from <code>PATH</code> when available, then a locally managed version, and otherwise downloads the latest stable Zig release for the supported host platform into the Marmotta home directory (see <a href="#marmotta-home-directory">Marmotta home directory</a>). If <code>zigVersion</code> is set, Marmotta ignores <code>PATH</code> and selects that exact managed version, downloading it if necessary. If the pinned version is not available for the host platform, the command fails instead of falling back to another version. If the download index includes a checksum, Marmotta verifies the downloaded archive. If <code>MARMOTTA_ZIG_DIR</code> is set, Marmotta uses only that Zig and never downloads one (see <a href="#existing-zig-installation">Existing Zig installation</a>).</p>
<p>Prepare Zig in advance:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> install</span></span></code></pre>
<p>List and remove toolchain versions managed by Marmotta:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> list</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> remove</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> 0.10.0</span></span></code></pre>
<p><code>list</code> and <code>remove</code> operate only on versions managed by Marmotta; they do not list, uninstall, or modify a system Zig executable found on <code>PATH</code>.</p>
<h3 id="existing-zig-installation"><a class="heading-anchor" href="#existing-zig-installation">Existing Zig installation</a></h3>
<p>Set <code>MARMOTTA_ZIG_DIR</code> to the directory of a Zig installation that already exists on the system, for example when downloads are blocked or the toolchain is provided by the organization and cannot be changed:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">export</span><span style="color:#24292E;--shiki-dark:#E1E4E8"> MARMOTTA_ZIG_DIR</span><span style="color:#D73A49;--shiki-dark:#F97583">=</span><span style="color:#24292E;--shiki-dark:#E1E4E8">/opt/zig-x86_64-linux-0.14.1</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> build</span></span></code></pre>
<ul>
<li>The directory must contain the Zig executable (<code>zig</code>, or <code>zig.exe</code> on Windows), as in the archives published on ziglang.org.</li>
<li>Marmotta uses this Zig for every command and never downloads Zig while the variable is set. It takes precedence over Zig on <code>PATH</code> and over the versions managed by Marmotta, and a <code>zigVersion</code> pin in the configuration is ignored.</li>
<li>If the directory does not contain a Zig executable that can be run, the command fails with <code>MARMOTTA_ZIG_DIR_UNAVAILABLE</code> and names the expected path. Marmotta does not fall back to another Zig.</li>
<li>The value follows the same rules as <code>MARMOTTA_HOME</code>: it must be an absolute path without leading or trailing whitespace, otherwise it is rejected with <code>MARMOTTA_ZIG_DIR_INVALID</code>. An empty value is treated as unset.</li>
<li>Marmotta never writes to this directory, and <code>list</code> and <code>remove</code> do not include or change it. Temporary build files still go to the Marmotta home directory, and Zig's global cache follows the rules described there.</li>
</ul>
<h3 id="marmotta-home-directory"><a class="heading-anchor" href="#marmotta-home-directory">Marmotta home directory</a></h3>
<p>Marmotta stores managed Zig toolchains (<code>toolchains/zig/&#x3C;version></code>) and temporary build files in its home directory. By default this is <code>.marmotta</code> in the user's home directory (<code>~/.marmotta</code> on Unix-like systems or <code>%USERPROFILE%\.marmotta</code> on Windows).</p>
<p>Set <code>MARMOTTA_HOME</code> to use another directory, for example when the home directory is read-only or not persistent, as on restricted CI runners or in containers:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">export</span><span style="color:#24292E;--shiki-dark:#E1E4E8"> MARMOTTA_HOME</span><span style="color:#D73A49;--shiki-dark:#F97583">=</span><span style="color:#24292E;--shiki-dark:#E1E4E8">/var/cache/marmotta</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">npx</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> marmotta</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> build</span></span></code></pre>
<ul>
<li>The value must be an absolute path. On Windows it must start with a drive letter (<code>D:\marmotta</code>) or be a UNC path (<code>\\server\share\marmotta</code>); root-relative paths such as <code>\marmotta</code> and device paths such as <code>\\?\</code> or <code>\\.\</code> are not accepted. <code>~</code> is not expanded, and values with leading or trailing whitespace are rejected instead of being trimmed. Invalid values are rejected with <code>MARMOTTA_HOME_INVALID</code>.</li>
<li>An empty value is treated as unset.</li>
<li>Marmotta creates the directory, and the subdirectories it needs, when a command first writes to it. If a directory cannot be created or written, for example when building, the command fails with <code>MARMOTTA_HOME_UNAVAILABLE</code> and names the directory and the cause. A failed Zig installation keeps its <code>ZIG_INSTALL_FAILED</code> code and includes the same details. Commands that write nothing, such as <code>marmotta list</code>, or <code>configure</code> and <code>install</code> when Zig is already available, also work with a read-only directory.</li>
<li>When <code>MARMOTTA_HOME</code> is set, Zig's global cache is placed in <code>&#x3C;MARMOTTA_HOME>/cache</code>, so builds do not write to the home directory. If <code>ZIG_GLOBAL_CACHE_DIR</code> is already set to a non-empty value, Marmotta leaves it unchanged. Without <code>MARMOTTA_HOME</code>, Marmotta does not change the cache location and Zig uses its own default.</li>
<li>Marmotta only removes files and directories it created, such as a Zig version removed with <code>marmotta remove</code> or temporary build directories. It never deletes or cleans the <code>MARMOTTA_HOME</code> directory itself, so it can point to a shared location.</li>
</ul>

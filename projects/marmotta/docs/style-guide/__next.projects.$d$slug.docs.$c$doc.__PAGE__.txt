19:T22d2,<h1 id="marmotta-style-guide">Marmotta Style Guide</h1>
<h2 id="welcome"><a class="heading-anchor" href="#welcome">Welcome</a></h2>
<p>Welcome to <em>Marmotta Style Guide</em>. This guide is here to provide you with a
conventional writing style for users writing developer documentation on our Open
Source framework. Each topic is precise and well explained to help you write
documentation users can easily understand and implement.</p>
<h2 id="who-is-this-guide-for"><a class="heading-anchor" href="#who-is-this-guide-for">Who is this guide for?</a></h2>
<p>This guide is for anyone who loves to build with Marmotta or wants to contribute
to our documentation. You do not need to be an expert in writing technical
documentation. This guide is here to help you.</p>
<p>Read the <a href="/projects/marmotta/docs/contributing/">CONTRIBUTING.md</a>
file on GitHub to join our Open Source folks.</p>
<h2 id="before-you-write"><a class="heading-anchor" href="#before-you-write">Before you write</a></h2>
<p>You need to know the following:</p>
<ul>
<li>JavaScript</li>
<li>TypeScript</li>
<li>Node.js</li>
<li>Git</li>
<li>GitHub</li>
<li>Markdown</li>
<li>HTTP</li>
<li>NPM</li>
</ul>
<h3 id="consider-your-audience"><a class="heading-anchor" href="#consider-your-audience">Consider your Audience</a></h3>
<p>Before you start writing, think about your audience. In this case, your audience
should already know, JavaScript, NPM, Node.js and native addon. It is necessary
to keep your readers in mind because they are the ones consuming your content.
You want to give as much useful information as possible. Consider the vital
things they need to know and how they can understand them. Use words and
references that readers can relate to easily. Ask for feedback from the
community, it can help you write better documentation that focuses on the user
and what you want to achieve.</p>
<h3 id="get-straight-to-the-point"><a class="heading-anchor" href="#get-straight-to-the-point">Get straight to the point</a></h3>
<p>Give your readers a clear and precise action to take. Start with what is most
important. This way, you can help them find what they need faster. Mostly,
readers tend to read the first content on a page, and many will not scroll
further.</p>
<p><strong>Example</strong></p>
<p>Less like this: Colons are very important to register a parametric path. It lets
the framework know there is a new parameter created. You can place the colon
before the parameter name so the parametric path can be created.</p>
<p>More Like this: To register a parametric path, put a colon before the parameter
name. Using a colon lets the framework know it is a parametric path and not a
static path.</p>
<h3 id="avoid-adding-video-or-image-content"><a class="heading-anchor" href="#avoid-adding-video-or-image-content">Avoid adding video or image content</a></h3>
<p>Do not add videos or screenshots to the documentation. It is easier to keep
under version control. Videos and images will eventually end up becoming
outdated as new updates keep developing. Instead, make a referral link or a
YouTube video. You can add links by using <code>[Title](https://www.websitename.com)</code>
in the markdown.</p>
<h3 id="avoid-plagiarism"><a class="heading-anchor" href="#avoid-plagiarism">Avoid plagiarism</a></h3>
<p>Make sure you avoid copying other people's work. Keep it as original as
possible. You can learn from what they have done and reference where it is from
if you use a particular quote from their work.</p>
<h2 id="word-choice"><a class="heading-anchor" href="#word-choice">Word Choice</a></h2>
<p>There are a few things you need to use and avoid when writing your documentation
to improve readability for readers and make documentation neat, direct, and
clean.</p>
<h3 id="when-to-use-the-second-person-you-as-the-pronoun"><a class="heading-anchor" href="#when-to-use-the-second-person-you-as-the-pronoun">When to use the second person "you" as the pronoun</a></h3>
<p>When writing articles or guides, your content should communicate directly to
readers in the second person ("you") addressed form. It is easier to give them
direct instruction on what to do on a particular topic.</p>
<p><strong>Example</strong></p>
<p>Less like this: we can use the following functions.</p>
<p>More like this: You can use the following functions.</p>
<blockquote>
<p>According to <a href="https://en.wikipedia.org/wiki/You" target="_blank" rel="noreferrer noopener">Wikipedia</a>, <em><strong>You</strong></em> is usually a second person pronoun.
Also, used to refer to an indeterminate person, as a more common alternative
to a very formal indefinite pronoun.</p>
</blockquote>
<h3 id="when-to-avoid-the-second-person-you-as-the-pronoun"><a class="heading-anchor" href="#when-to-avoid-the-second-person-you-as-the-pronoun">When to avoid the second person "you" as the pronoun</a></h3>
<p>One of the main rules of formal writing such as reference documentation, or API
documentation, is to avoid the second person ("you") or directly addressing the
reader.</p>
<p><strong>Example</strong></p>
<p>Less like this: You can use the following recommendation as an example.</p>
<p>More like this: As an example, the following recommendations should be
referenced.</p>
<h3 id="avoid-using-contractions"><a class="heading-anchor" href="#avoid-using-contractions">Avoid using contractions</a></h3>
<p>Contractions are the shortened version of written and spoken forms of a word,
i.e. using "don't" instead of "do not". Avoid contractions to provide a more
formal tone.</p>
<h3 id="avoid-using-condescending-terms"><a class="heading-anchor" href="#avoid-using-condescending-terms">Avoid using condescending terms</a></h3>
<p>Condescending terms are words that include:</p>
<ul>
<li>Just</li>
<li>Easy</li>
<li>Simply</li>
<li>Basically</li>
<li>Obviously</li>
</ul>
<p>Not everyone who reads the documentation has the same level of understanding.</p>
<h3 id="starting-with-a-verb"><a class="heading-anchor" href="#starting-with-a-verb">Starting with a verb</a></h3>
<p>Mostly start your description with a verb, which makes it simple and precise for
the reader to follow. Prefer using present tense because it is easier to read
and understand than the past or future tense.</p>
<p><strong>Example</strong></p>
<p>Less like this: There is a need for Node.js to be installed before you can be
able to use Marmotta.</p>
<p>More like this: Install Node.js to make use of Marmotta.</p>
<h3 id="grammatical-moods"><a class="heading-anchor" href="#grammatical-moods">Grammatical moods</a></h3>
<p>Grammatical moods are a great way to express your writing. Avoid sounding too
bossy while making a direct statement. Know when to switch between indicative,
imperative, and subjunctive moods.</p>
<p><strong>Indicative</strong> - Use when making a factual statement or question.</p>
<p>Example: Since there is no testing framework available, "Marmotta recommends ways
to write tests".</p>
<p><strong>Imperative</strong> - Use when giving instructions, actions, commands, or when you
write your headings.</p>
<p>Example: Install dependencies before starting development.</p>
<p><strong>Subjunctive</strong> -  Use when making suggestions, hypotheses, or non-factual
statements.</p>
<h3 id="use-active-voice-instead-of-passive"><a class="heading-anchor" href="#use-active-voice-instead-of-passive">Use <strong>active</strong> voice instead of <strong>passive</strong></a></h3>
<p>Using active voice is a more compact and direct way of conveying your
documentation.</p>
<p><strong>Example</strong></p>
<p>Passive: The node dependencies and packages are installed by npm.</p>
<p>Active:  npm installs packages and node dependencies.</p>
<h2 id="writing-style"><a class="heading-anchor" href="#writing-style">Writing Style</a></h2>
<h3 id="documentation-titles"><a class="heading-anchor" href="#documentation-titles">Documentation titles</a></h3>
<p>When creating a new guide, API, or reference in the <code>/docs/</code> directory, use
short titles that best describe the topic of your documentation. Name your files
in kebab-cases and avoid Raw or camelCase. To learn more about kebab-case you
can visit this medium article on <a href="https://medium.com/better-programming/string-case-styles-camel-pascal-snake-and-kebab-case-981407998841" target="_blank" rel="noreferrer noopener">Case
Styles</a>.</p>
<p><strong>Examples</strong>:</p>
<blockquote>
<p><code>adding-test.md</code>,</p>
</blockquote>
<p><code>removing-requests.md</code>.</p>
<h3 id="hyperlinks"><a class="heading-anchor" href="#hyperlinks">Hyperlinks</a></h3>
<p>Hyperlinks should have a clear title of what they reference.</p>
<p>For example: <a href="/projects/marmotta/docs/contributing/">Marmotta contributing guide</a>.</p>

3d:T1d68,<h1 id="marmotta-is-an-open-open-source-project">Marmotta is an OPEN Open Source Project</h1>
<h2 id="what"><a class="heading-anchor" href="#what">What?</a></h2>
<p>Individuals making significant and valuable contributions are given
commit-access to the project to contribute as they see fit. This project is more
like an open wiki than a standard guarded open source project.</p>
<p>See our <a href="/projects/marmotta/docs/docs/contributing/">informal contributing guide</a> for more
details on contributing to this project.</p>
<h3 id="i-want-to-be-a-collaborator"><a class="heading-anchor" href="#i-want-to-be-a-collaborator">I want to be a collaborator!</a></h3>
<p>If you think you meet the above criteria and we have not invited you yet, we are
sorry! Feel free to reach out to a <a href="https://github.com/napi-bindings/marmotta#team" target="_blank" rel="noreferrer noopener">Lead
Maintainer</a> privately with a few links
to your valuable contributions. Read the <a href="/projects/marmotta/docs/governance/">GOVERNANCE</a> to get more
information.</p>
<h2 id="rules"><a class="heading-anchor" href="#rules">Rules</a></h2>
<p>There are a few basic ground rules for contributors:</p>
<ol>
<li><strong>No <code>--force</code> pushes</strong> on <code>main</code> or modifying the Git history in any way
after a PR has been merged.</li>
<li><strong>Non-main branches</strong> ought to be used for ongoing work.</li>
<li><strong>External API changes and significant modifications</strong> ought to be subject to
an <strong>internal pull request</strong> to solicit feedback from other contributors.</li>
<li>Internal pull requests to solicit feedback are <em>encouraged</em> for any other
non-trivial contribution but are left to the discretion of the contributor.</li>
<li>Contributors should attempt to adhere to the prevailing code style.</li>
<li>At least two contributors, or one core member, must approve pull requests
before merging.</li>
<li>All integrated CI services must be green before a pull request can be merged.</li>
<li>A lead maintainer must merge SemVer-major changes in this repository.</li>
<li>If it is not possible to reach a consensus in a pull request, the decision
is left to the lead maintainer's team.</li>
<li>Pure-AI contributions with no human in the loop are not welcome. Pull
requests <em><strong>MUST</strong></em> be opened by a human. Pull requests opened by bots not
managed by the napi-bindings organization will result in the bot being banned
from the organization.</li>
</ol>
<h2 id="releases"><a class="heading-anchor" href="#releases">Releases</a></h2>
<p>Declaring formal releases remains the prerogative of the lead maintainers. Do
not bump version numbers in pull requests.</p>
<p>Bump the version with <code>npm version</code> rather than editing <code>package.json</code> by hand:
its <code>version</code> lifecycle script updates the constant in <code>src/version.ts</code> and
stages it, so the npm package and the standalone executables report the same
version. (<code>npm test</code> also fails when the two drift.)</p>
<p>Pushing a <code>v*</code> tag triggers the <code>Release binaries</code> workflow, which builds the
standalone executables for all supported platforms with <code>bun build --compile</code>,
runs <code>scripts/smoke.mjs</code> against each one, and attaches them together with
<code>SHA256SUMS</code> and provenance attestations to the GitHub release of that tag. The
tag must match the version in <code>package.json</code> or the workflow fails. Maintainers
can also run the workflow manually from the Actions tab to test it before
tagging; the binaries are then only uploaded as workflow artifacts.</p>

<h3 id="onboarding-collaborators"><a class="heading-anchor" href="#onboarding-collaborators">Onboarding Collaborators</a></h3>
<p>Welcome to the team! We are happy to have you. Before you start, please complete
the following tasks:</p>
<ol>
<li>Set up 2 factor authentication for GitHub and NPM
<ul>
<li><a href="https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa" target="_blank" rel="noreferrer noopener">GitHub
2FA</a></li>
<li><a href="https://docs.npmjs.com/about-two-factor-authentication/" target="_blank" rel="noreferrer noopener">NPM 2FA</a></li>
</ul>
</li>
<li>Open a pull request to
<a href="https://github.com/napi-bindings/marmotta/pulls" target="_blank" rel="noreferrer noopener"><code>napi-bindings/marmotta:HEAD</code></a> that adds
your name, username, and email to the team in the <a href="/projects/marmotta/">README.md</a> and
<a href="https://github.com/napi-bindings/marmotta/blob/main/package.json" target="_blank" rel="noreferrer noopener">package.json</a> files. The member lists are sorted alphabetically by last
name; make sure to add your name in the proper order..</li>
<li>Optionally, the person can be added as an Open Collective member
by the lead team.</li>
</ol>
<h3 id="offboarding-collaborators"><a class="heading-anchor" href="#offboarding-collaborators">Offboarding Collaborators</a></h3>
<p>We are thankful to you and we are really glad to have worked with you. We'd be
really happy to see you here again if you want to come back, but for now the
person that did the onboarding must:</p>
<ol>

themselves to the <em>Past Collaborators</em> section.</li>
</ol>

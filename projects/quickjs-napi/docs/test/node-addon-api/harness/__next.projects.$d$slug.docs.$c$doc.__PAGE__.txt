<p><code>test/node-addon-api</code> holds the headers (<code>napi.h</code>, <code>napi-inl.h</code>,
<code>napi-inl.deprecated.h</code>), the license and the <code>test/</code> directory of
node-addon-api (version in <code>NODE_ADDON_API_VERSION</code>), copied by</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">python3</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> tools/sync_node_addon_api.py</span><span style="color:#D73A49;--shiki-dark:#F97583"> &#x3C;</span><span style="color:#032F62;--shiki-dark:#9ECBFF">node-addon-api</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> checkou</span><span style="color:#24292E;--shiki-dark:#E1E4E8">t</span><span style="color:#D73A49;--shiki-dark:#F97583">></span></span></code></pre>

<h2 id="notes"><a class="heading-anchor" href="#notes">Notes</a></h2>
<ul>
<li><code>async_progress_worker</code> runs alone (<code>RUN_SERIAL</code>): its
<code>SignalAfterProgressTestWorker</code> case is racy upstream (Send then Signal
from the worker thread; if the loop thread handles the first call in
between, the second sees no data), under Node.js as well.</li>
<li>The bindings are compiled with <code>-fno-sanitize=alignment</code>:
<code>DataView::ReadData</code> in <code>napi-inl.h</code> reads through misaligned pointers.</li>
<li><code>test/lsan.supp</code> suppresses the leaks of the test code and of
<code>Napi::ThreadSafeFunction</code> (its call wrappers are deleted only when the
callback returns normally), as under Node.js.</li>
<li>Running the suite found three differences that were fixed in the runtime:
<code>napi_define_class</code> with an instance key defined twice (V8 templates
replace), weak references to objects that QuickJS freed at once (kept
objects, see the README), and <code>process.exit()</code> tearing the environment
down (Node.js does not).</li>

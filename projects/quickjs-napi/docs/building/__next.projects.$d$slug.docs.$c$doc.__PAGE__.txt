<h3 id="debug-builds-and-the-c-stack"><a class="heading-anchor" href="#debug-builds-and-the-c-stack">Debug builds and the C stack</a></h3>
<p>With Clang (<code>zig cc</code> included), Debug builds compile the <strong>QuickJS library
itself with <code>-O1</code></strong>: at <code>-O0</code> its interpreter loop needs about 64 KiB of C
stack per JavaScript call, and QuickJS's 1 MiB stack limit would stop at about
16 nested calls. Our own code keeps the Debug flags, and QuickJS keeps its
assertions.</p>

<h2 id="windows"><a class="heading-anchor" href="#windows">Windows</a></h2>
<p>QuickJS does not support Microsoft Visual C++: the Visual Studio generators
(and clang-cl) are rejected at configure time. Use a MinGW-w64 toolchain with
Ninja, as quickjs-build does.</p>
<h3 id="zig"><a class="heading-anchor" href="#zig">zig</a></h3>
<p>Install the zig version in <code>../quickjs-build/.zigversion</code> (for example
<code>winget install zig.zig</code>). <code>zig</code> must be in <code>PATH</code>, or set the <code>ZIG</code>
environment variable. Use the presets, which pass the toolchain file:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">cmake</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --preset</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> windows-zig-debug</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">cmake</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --build</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --preset</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> windows-zig-debug</span></span>
<span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">ctest</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> --preset</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> windows-zig-debug</span></span></code></pre>
<p>In VS Code (CMake Tools) select the configure preset <em>Windows x64 - zig -
Debug</em>. Do <strong>not</strong> use a "zig" compiler <em>kit</em>: a kit sets <code>CMAKE_AR=zig;ar</code>
without the toolchain file, and Ninja then runs the literal command <code>zig;ar</code>
(<code>error: unknown command: ;ar</code>). If <code>build/</code> still holds a tree configured
with a kit or a Visual Studio generator (<code>build/CMakeCache.txt</code>), delete it
once before the first configure.</p>
<h3 id="msys2"><a class="heading-anchor" href="#msys2">MSYS2</a></h3>
<p>From a UCRT64 shell (<code>pacman -S mingw-w64-ucrt-x86_64-{gcc,cmake,ninja}</code>),
use the generic commands above.</p>
<h3 id="addons-built-with-msvc"><a class="heading-anchor" href="#addons-built-with-msvc">Addons built with MSVC</a></h3>
<p>Addons compiled with MSVC by node-gyp still load in the MinGW-built
<code>quickjs-napi.exe</code>: Node-API is a plain C ABI, and node-gyp's delay-load hook
resolves the <code>napi_*</code> imports from the running executable.</p>

<h2 id="release-packages"><a class="heading-anchor" href="#release-packages">Release packages</a></h2>
<p><code>.github/workflows/release.yml</code> runs when a GitHub release is <strong>published</strong>
(or by hand, <code>workflow_dispatch</code>, which does everything but the upload):</p>
<ol>
<li><strong>prepare</strong>: reads <code>project(quickjs-napi VERSION x.y.z)</code> from
<code>CMakeLists.txt</code> and fails if the release tag (<code>x.y.z</code> or <code>vx.y.z</code>)
differs; picks the latest release of quickjs-build (or the
<code>quickjs_build_ref</code> input).</li>
<li><strong>ci</strong>: the whole CI suite (<code>ci.yml</code>) on that quickjs-build.</li>
<li><strong>build</strong>: one package per platform, Release, tests off, installed and
zipped as <code>quickjs-napi-&#x3C;version>-&#x3C;platform>.zip</code> (the layout of
<a href="#installing">Installing</a>).</li>
<li><strong>smoke</strong>: <code>test/package/smoke.sh</code> on each package, on a machine or
emulator of its platform.</li>
<li><strong>publish</strong>: only if everything above passed, uploads the zip files and
<code>SHA256SUMS</code> to the release.</li>

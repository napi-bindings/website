<h2 id="buffers"><a class="heading-anchor" href="#buffers">Buffers</a></h2>
<p>Buffers are instances of a <strong>minimal Node.js <code>Buffer</code></strong> embedded in the
library (<code>src/buffer.js</code>). As in Node.js, a buffer is a <code>FastBuffer</code>, a
<code>Uint8Array</code> subclass whose prototype is <code>Buffer.prototype</code>, so typed-array
APIs work on it too. The class provides:</p>
<table>
<thead>
<tr>
<th></th>
<th></th>
</tr>
</thead>
<tbody>
<tr>
<td>Static</td>
<td><code>Buffer.from</code>, <code>alloc</code>, <code>allocUnsafe</code>, <code>allocUnsafeSlow</code>, <code>isBuffer</code>, <code>isEncoding</code>, <code>byteLength</code>, <code>concat</code>, <code>compare</code>, <code>poolSize</code></td>
</tr>
<tr>
<td>Prototype</td>
<td><code>toString</code>, <code>toLocaleString</code>, <code>write</code>, <code>equals</code>, <code>compare</code>, <code>copy</code>, <code>fill</code>, <code>slice</code>, <code>subarray</code>, <code>toJSON</code>, <code>indexOf</code>, <code>includes</code></td>
</tr>
<tr>
<td>Encodings</td>
<td><code>utf8</code>, <code>utf16le</code> (<code>ucs2</code>), <code>latin1</code> (<code>binary</code>), <code>ascii</code>, <code>hex</code>, <code>base64</code>, <code>base64url</code></td>
</tr>
</tbody>
</table>
<p>The library installs no global. The embedder gets the class with
<a href="/projects/quickjs-napi/docs/embedding/#qjsnapi_host_get_buffer"><code>qjsnapi_host_get_buffer</code></a>; the
<code>quickjs-napi</code> executable exposes it as <code>globalThis.Buffer</code> and
<code>require('buffer').Buffer</code>.</p>

<h2 id="async-context"><a class="heading-anchor" href="#async-context">Async context</a></h2>
<p>Node.js associates native callbacks with <code>async_hooks</code> resources, so that
<code>AsyncLocalStorage</code> and async stack traces follow them. <strong>quickjs-napi has no
<code>async_hooks</code></strong>: an async context only records that it exists, and the
resource and its name are validated but not used. The functions are provided
so that addons using them load and behave correctly.</p>
<h3 id="napi_async_init"><a class="heading-anchor" href="#napi_async_init"><code>napi_async_init</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_async_init</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">async_resource</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                            napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">async_resource_name</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                            napi_async_context </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>

<code>async_resource_name</code> is required. Contexts never destroyed are freed at
teardown.</p>

<h3 id="napi_make_callback"><a class="heading-anchor" href="#napi_make_callback"><code>napi_make_callback</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_make_callback</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_async_context </span><span style="color:#E36209;--shiki-dark:#FFAB70">async_context</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                               napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">recv</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">func</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> argc</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                               const</span><span style="color:#24292E;--shiki-dark:#E1E4E8"> napi_value </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">argv</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Calls <code>func</code> with <code>this = recv</code> the way Node.js calls JavaScript from native
code that was not itself called by JavaScript (an I/O completion, a timer of
the addon). Compared to <code>napi_call_function</code>:</p>
<ul>
<li>the call runs inside a <strong>callback scope</strong>: when it is the outermost one and
no JavaScript is on the stack, the host's checkpoint (microtasks,
<code>process.nextTick</code>) runs after <code>func</code> returns, as Node's
<code>InternalCallbackScope</code> does;</li>
<li><code>recv</code> is converted with <code>ToObject</code> (<code>null</code> / <code>undefined</code> give
<code>napi_object_expected</code> with a <code>TypeError</code> pending);</li>
<li><code>func</code> must be a function (<code>napi_function_expected</code>);</li>
<li><code>async_context</code> may be <code>NULL</code>; at most 65535 arguments.</li>
</ul>
<p><code>result</code> is optional.</p>
<h2 id="callback-scopes"><a class="heading-anchor" href="#callback-scopes">Callback scopes</a></h2>
<h3 id="napi_open_callback_scope"><a class="heading-anchor" href="#napi_open_callback_scope"><code>napi_open_callback_scope</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_open_callback_scope</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">resource_object</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                                     napi_async_context </span><span style="color:#E36209;--shiki-dark:#FFAB70">context</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                                     napi_callback_scope </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Opens a callback scope, for native code that calls into JavaScript several
times (with <code>napi_call_function</code>) and wants a single checkpoint at the end.
<code>context</code> is required; <code>resource_object</code> is ignored, as in Node.js.</p>
<h3 id="napi_close_callback_scope"><a class="heading-anchor" href="#napi_close_callback_scope"><code>napi_close_callback_scope</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_close_callback_scope</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                                      napi_callback_scope </span><span style="color:#E36209;--shiki-dark:#FFAB70">scope</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Closes the scope. When it is the outermost callback scope of the host, no
JavaScript is below the current native code, and no exception is pending,
the checkpoint runs here. <code>napi_callback_scope_mismatch</code> when no callback
scope is open.</p>
<pre class="mermaid">flowchart TD
    A["napi_close_callback_scope / end of napi_make_callback"] --> B{"outermost callback scope?"}
    B -- no --> Z["nothing more"]
    B -- yes --> C{"JavaScript below the native code?&#x3C;br/>(native_depth > 0)"}
    C -- yes --> Z
    C -- no --> D{"exception pending or env tearing down?"}
    D -- yes --> Z
    D -- no --> E["checkpoint: pending promise jobs&#x3C;br/>(or the embedder's checkpoint),&#x3C;br/>then kept objects cleared"]
</pre>
<p>Inside a Node-API callback called by JavaScript (the usual case) the caller's
own frame is still on the stack, so nothing runs early, exactly as in Node.js.</p>

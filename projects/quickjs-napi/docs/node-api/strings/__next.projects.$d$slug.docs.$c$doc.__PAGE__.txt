<h2 id="how-strings-are-converted"><a class="heading-anchor" href="#how-strings-are-converted">How strings are converted</a></h2>
<p>JavaScript strings are sequences of UTF-16 code units. QuickJS has no public
UTF-16 API, but its UTF-8 entry points are lossless at the code-unit level,
and quickjs-napi relies on that:</p>
<pre class="mermaid">flowchart LR
    U16["UTF-16 buffer&#x3C;br/>(may contain lone surrogates)"] -- "pairs: 4-byte sequences&#x3C;br/>lone surrogates: 3-byte sequences" --> W["WTF-8"]
    W -- JS_NewStringLen --> S["QuickJS string"]
    L1["latin1 buffer"] -- "each byte = one code point" --> U8["UTF-8"] -- JS_NewStringLen --> S
    S -- "JS_ToCStringLen2(cesu8 = 1):&#x3C;br/>one sequence per code unit" --> C["CESU-8"]
    C -- "decode unit by unit" --> O16["UTF-16 / latin1 output"]
    S -- "JS_ToCStringLen2(cesu8 = 0)" --> W2["WTF-8"] -- "lone surrogates -> U+FFFD" --> O8["UTF-8 output"]
</pre>
<ul>
<li><strong>Creation</strong> is exact: a UTF-16 buffer with lone surrogates round-trips
unchanged.</li>
<li><strong>Extraction</strong> follows V8 as used by Node.js: lengths are counted in code
units for latin1 and UTF-16 and in bytes for UTF-8; UTF-8 output never ends
with a partial character and replaces lone surrogates with U+FFFD; latin1
output keeps the low byte of each code unit (V8 <code>WriteOneByte</code>).</li>
</ul>
<h3 id="length-arguments"><a class="heading-anchor" href="#length-arguments">Length arguments</a></h3>
<p>Creation functions take a <code>length</code> in code units (bytes for latin1 and
UTF-8, <code>char16_t</code> for UTF-16) or <code>NAPI_AUTO_LENGTH</code> for a NUL-terminated
string. <code>str</code> may be <code>NULL</code> only when <code>length</code> is <code>0</code>. A length above
<code>INT32_MAX</code> (other than <code>NAPI_AUTO_LENGTH</code>) returns <code>napi_invalid_arg</code>.</p>

<h2 id="external-strings"><a class="heading-anchor" href="#external-strings">External strings</a></h2>
<p>V8 can create a string that points to memory owned by the addon. QuickJS
cannot: its strings always own their content.</p>

<h2 id="property-keys"><a class="heading-anchor" href="#property-keys">Property keys</a></h2>
<p>V8 internalizes these strings so that property lookups with them are faster.
QuickJS turns any string used as a property key into an <em>atom</em>, so these
functions create <strong>ordinary strings</strong>; using them as keys is as fast as with
any other string.</p>

<h3 id="napi_get_value_string_latin1"><a class="heading-anchor" href="#napi_get_value_string_latin1"><code>napi_get_value_string_latin1</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_get_value_string_latin1</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">value</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                                         char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">buf</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> bufsize</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>

of each unit (characters above U+00FF are therefore mangled, as in Node.js).
Lengths are in code units.</p>
<h3 id="napi_get_value_string_utf8"><a class="heading-anchor" href="#napi_get_value_string_utf8"><code>napi_get_value_string_utf8</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_get_value_string_utf8</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(napi_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, napi_value </span><span style="color:#E36209;--shiki-dark:#FFAB70">value</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                                       char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">buf</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> bufsize</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>

<p>Copies the UTF-16 code units exactly (lone surrogates included). Lengths are
in code units; a buffer that is too short may end between the two halves of

<h3 id="napi_get_last_error_info"><a class="heading-anchor" href="#napi_get_last_error_info"><code>napi_get_last_error_info</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_get_last_error_info</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                                     const</span><span style="color:#24292E;--shiki-dark:#E1E4E8"> napi_extended_error_info </span><span style="color:#D73A49;--shiki-dark:#F97583">**</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Returns a pointer to the env's last-error record: <code>error_code</code> is the status of
the last Node-API call that failed (or <code>napi_ok</code>), <code>error_message</code> a static
English message (see the <a href="/projects/quickjs-napi/docs/node-api/#status-codes-and-the-last-error">status table</a>).
<code>engine_error_code</code> and <code>engine_reserved</code> are always <code>0</code> / <code>NULL</code>.</p>
<ul>
<li>The record belongs to the env and is overwritten by the next call: copy what
you need before calling another function.</li>
<li>This function never changes the last error itself, so it can be called
repeatedly. It always returns <code>napi_ok</code> (or <code>napi_invalid_arg</code> for a <code>NULL</code>
argument).</li>
<li>Each native callback starts with a clear last error, as in Node.js.</li>
</ul>
<h3 id="napi_get_version"><a class="heading-anchor" href="#napi_get_version"><code>napi_get_version</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_get_version</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">uint32_t</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Stores <code>10</code>, the highest Node-API version this build supports (the same value
as <code>qjsnapi_napi_version()</code>). Experimental APIs (<code>NAPI_EXPERIMENTAL</code>) are not
provided.</p>
<h3 id="napi_get_node_version"><a class="heading-anchor" href="#napi_get_node_version"><code>napi_get_node_version</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_get_node_version</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>

<h3 id="node_api_get_module_file_name"><a class="heading-anchor" href="#node_api_get_module_file_name"><code>node_api_get_module_file_name</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">node_api_get_module_file_name</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                                          const</span><span style="color:#D73A49;--shiki-dark:#F97583"> char</span><span style="color:#D73A49;--shiki-dark:#F97583"> **</span><span style="color:#E36209;--shiki-dark:#FFAB70">result</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Stores the absolute <code>file://</code> URL of the addon this env belongs to, encoded
like Node's <code>url.pathToFileURL</code> (percent-encoding, Windows drive letters as

<h3 id="napi_add_env_cleanup_hook"><a class="heading-anchor" href="#napi_add_env_cleanup_hook"><code>napi_add_env_cleanup_hook</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_add_env_cleanup_hook</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                                      napi_cleanup_hook </span><span style="color:#E36209;--shiki-dark:#FFAB70">fun</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">arg</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Registers <code>fun(arg)</code> to run when the env is torn down
(<code>qjsnapi_host_destroy</code>, or the normal end of the executable). Hooks run in
<strong>reverse order of registration</strong> (LIFO), interleaved with the async cleanup
hooks and the library's own hooks (thread-safe functions), with JavaScript
already disabled.</p>
<ul>
<li>Registering the same <code>(fun, arg)</code> pair twice is a <strong>fatal error</strong>, as in
Node.js (where it is a <code>CHECK</code> failure).</li>
<li>Hooks do <strong>not</strong> run when the executable ends with <code>process.exit()</code> or a
fatal exception, as in Node.js.</li>
</ul>
<h3 id="napi_remove_env_cleanup_hook"><a class="heading-anchor" href="#napi_remove_env_cleanup_hook"><code>napi_remove_env_cleanup_hook</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_remove_env_cleanup_hook</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(node_api_basic_env </span><span style="color:#E36209;--shiki-dark:#FFAB70">env</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                                         napi_cleanup_hook </span><span style="color:#E36209;--shiki-dark:#FFAB70">fun</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">arg</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Unregisters the hook registered with the same <code>(fun, arg)</code>. Removing a pair
that is not registered does nothing and returns <code>napi_ok</code>.</p>

<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_add_async_cleanup_hook</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(</span></span>

<h3 id="napi_remove_async_cleanup_hook"><a class="heading-anchor" href="#napi_remove_async_cleanup_hook"><code>napi_remove_async_cleanup_hook</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">napi_status </span><span style="color:#6F42C1;--shiki-dark:#B392F0">napi_remove_async_cleanup_hook</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">    napi_async_cleanup_hook_handle </span><span style="color:#E36209;--shiki-dark:#FFAB70">remove_handle</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Has two meanings, as in Node.js:</p>
<ul>
<li><strong>before teardown</strong>, it unregisters the hook, which will not run;</li>
<li><strong>after the hook started</strong>, it signals that the asynchronous cleanup is
complete, so the teardown can stop waiting for it.</li>
</ul>
<p>The handle is freed in both cases and must not be used again. Returns
<code>napi_invalid_arg</code> for <code>NULL</code>.</p>
<h3 id="napi_fatal_error"><a class="heading-anchor" href="#napi_fatal_error"><code>napi_fatal_error</code></a></h3>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">NAPI_NO_RETURN </span><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> napi_fatal_error</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(</span><span style="color:#D73A49;--shiki-dark:#F97583">const</span><span style="color:#D73A49;--shiki-dark:#F97583"> char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">location</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> location_len</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                                     const</span><span style="color:#D73A49;--shiki-dark:#F97583"> char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">message</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> message_len</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Prints <code>FATAL ERROR: &#x3C;location> &#x3C;message></code> on stderr and ends the process
immediately: <code>abort()</code> on Linux and macOS, <code>_exit(134)</code> on Windows (like
Node.js, which avoids the Windows Error Reporting dialog). No cleanup runs.
Both lengths accept <code>NAPI_AUTO_LENGTH</code>; <code>location</code> and <code>message</code> may be

<p>Legacy registration used by addons built with the old <code>NAPI_MODULE</code> macro
from a static constructor. When called <strong>while <code>qjsnapi_load_addon</code> is opening
a library</strong>, the module is attached to that load and its <code>nm_register_func</code>
becomes the initializer (only when the library does not export
<code>napi_register_module_v1</code>, which takes precedence). The record is remembered,
so loading the same file again reuses it even though the constructor does not
run a second time.</p>

<h3 id="functions-that-run-javascript"><a class="heading-anchor" href="#functions-that-run-javascript">Functions that run JavaScript</a></h3>
<p>Some functions may call into JavaScript (getters, setters, <code>valueOf</code>,
proxies, user callbacks). These <strong>refuse to start</strong> when an exception is
already pending (<code>napi_pending_exception</code>) or when the env can no longer run
JavaScript (<code>napi_cannot_run_js</code>, or <code>napi_pending_exception</code> for modules
built for Node-API &#x3C; 10). They are marked <strong>JS</strong> in the
<a href="#function-index">function index</a>. The other functions only touch C
bookkeeping or create values, and work even with an exception pending: this
is what lets an addon build an error message while an exception is pending.</p>
<p>When JavaScript throws during a call, the function returns
<code>napi_pending_exception</code> and <strong>the exception stays pending</strong>, exactly as in
Node.js. Returning from the native callback then propagates it to the
JavaScript caller. Use <code>napi_is_exception_pending</code> and
<code>napi_get_and_clear_last_exception</code> to handle it in C.</p>
<h3 id="basic-env"><a class="heading-anchor" href="#basic-env">Basic env</a></h3>
<p>Functions whose first parameter is <code>node_api_basic_env</code> (cleanup hooks,
instance data, <code>napi_delete_reference</code>, <code>napi_adjust_external_memory</code>,
<code>napi_get_uv_event_loop</code>, ...) may be called from a <em>basic finalizer</em>
(<code>node_api_basic_finalize</code>). In quickjs-napi every finalizer, basic or not,
runs <strong>outside the garbage collector</strong> (from the event loop or at teardown),
so calling other functions from a basic finalizer never causes the fatal
error Node.js raises; the distinction is kept for source compatibility.</p>
<h3 id="values-and-threads"><a class="heading-anchor" href="#values-and-threads">Values and threads</a></h3>
<ul>
<li>A <code>napi_value</code> is valid until the handle scope it was created in is closed.
Values created in a native callback are released when the callback returns,
unless they are returned, escaped, or kept in a <code>napi_ref</code>.</li>
<li>Every function except the thread-safe function ones
(<code>napi_call_threadsafe_function</code>, <code>napi_acquire_threadsafe_function</code>,
<code>napi_release_threadsafe_function</code>,
<code>napi_get_threadsafe_function_context</code>) must be called on the thread that
runs the event loop. <code>execute</code> callbacks of async work run on the thread
pool and must not call Node-API functions that take an env.</li>
</ul>

addon, then:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#6F42C1;--shiki-dark:#B392F0">quickjs-napi</span><span style="color:#005CC5;--shiki-dark:#79B8FF"> -e</span><span style="color:#032F62;--shiki-dark:#9ECBFF"> "console.log(require('./build/Release/addon.node').add(2, 3))"</span></span></code></pre>
<p>The same binary loads in Node.js. node-addon-api (C++) and napi-rs (Rust)
addons work the same way; the node-addon-api 8.9.2 test suite runs in CI
(<a href="/projects/quickjs-napi/docs/testing/">testing.md</a>).</p>
<p>The module API version is chosen by the addon at build time (<code>NAPI_VERSION</code>,
exported through <code>node_api_module_get_api_version_v1</code>). It is 8 when the
addon does not declare one, and changes a few behaviours: which values
<code>napi_create_reference</code> accepts, the status of
<a href="#functions-that-run-javascript">functions that run JavaScript</a> during
teardown, and the <a href="/projects/quickjs-napi/docs/node-api/async/#exceptions-in-call_js_cb">thread-safe function exception policy</a>.</p>

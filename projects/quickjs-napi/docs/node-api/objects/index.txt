<h2 id="common-rules"><a class="heading-anchor" href="#common-rules">Common rules</a></h2>
<p>These follow Node.js (<code>src/js_native_api_v8.cc</code>):</p>
<ul>
<li><strong>The receiver goes through <code>ToObject</code>.</strong> Primitives are wrapped (so
<code>napi_get_named_property(env, a_string, "length", ...)</code> works), while <code>null</code>
and <code>undefined</code> throw a <code>TypeError</code> and return <code>napi_object_expected</code> with
the exception pending.</li>
<li><strong>Keys go through <code>ToPropertyKey</code>.</strong> A <code>napi_value</code> key may be any value: a
number becomes its string form, an object is converted with <code>toString</code> /
<code>Symbol.toPrimitive</code>, which may run user code. Only <code>napi_has_own_property</code>
and <code>napi_define_properties</code> require a string or symbol
(<code>napi_name_expected</code>).</li>
<li><strong>Setting is a sloppy-mode <code>[[Set]]</code>.</strong> Assigning to a read-only property or
to a frozen object <strong>fails silently</strong> and returns <code>napi_ok</code>, like
<code>v8::Object::Set</code>. Setters and proxy <code>set</code> traps run.</li>
<li><strong>Deleting is a sloppy-mode <code>delete</code>.</strong> A non-configurable property is not
deleted, and <code>*result</code> is <code>false</code>; the call still returns <code>napi_ok</code>.</li>
</ul>

<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">  void</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#24292E;--shiki-dark:#E1E4E8">data;</span><span style="color:#6A737D;--shiki-dark:#6A737D">                /* passed to method / getter / setter */</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">} napi_property_descriptor;</span></span></code></pre>
<table>
<thead>
<tr>
<th>Descriptor</th>
<th>Defines</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>getter</code> and/or <code>setter</code></td>
<td>an accessor property; a missing half is <code>undefined</code>; <code>napi_writable</code> is ignored</td>
</tr>
<tr>
<td><code>method</code></td>
<td>a data property whose value is a new function (named after nothing, <code>length</code> 0) calling <code>method</code> with <code>data</code></td>
</tr>
<tr>
<td><code>value</code> (or nothing)</td>
<td>a data property holding <code>value</code> (or <code>undefined</code>)</td>
</tr>
</tbody>
</table>
<p>Attributes: <code>napi_writable</code>, <code>napi_enumerable</code>, <code>napi_configurable</code>, and the
combinations <code>napi_default</code> (none), <code>napi_default_method</code> (writable +
configurable, like class methods) and <code>napi_default_jsproperty</code> (all three,
like an assignment). <code>napi_static</code> is only meaningful for
<a href="/projects/quickjs-napi/docs/node-api/functions/#napi_define_class"><code>napi_define_class</code></a>.</p>
<p>Definitions are applied in order and stop at the first failure:</p>
<ul>
<li>a key that is neither <code>utf8name</code> nor a string/symbol <code>name</code> returns
<code>napi_name_expected</code>;</li>
<li>a definition the object refuses (redefining a non-configurable property,
adding to a non-extensible object) returns <code>napi_invalid_arg</code> for data and
accessor properties and <code>napi_generic_failure</code> for methods, as in Node.js.</li>
</ul>

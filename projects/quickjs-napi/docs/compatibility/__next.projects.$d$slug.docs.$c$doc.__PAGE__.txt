19:T2092,<h1 id="compatibility-with-nodejs">Compatibility with Node.js</h1>
<p>quickjs-napi reproduces the Node-API behaviour of <strong>Node.js 22.23.4</strong>: same
statuses, same pending exceptions, same error codes and messages, same
finalizer ordering. This page lists every known difference, so that addon
authors know what to expect. Each item links to the function reference.</p>
<ul>
<li><a href="#deviations-in-the-api">Deviations in the API</a></li>
<li><a href="#differences-that-come-from-quickjs">Differences that come from QuickJS</a></li>
<li><a href="#behaviour-that-is-defined-here-but-not-in-nodejs">Behaviour that is defined here but not in Node.js</a></li>
<li><a href="#not-provided">Not provided</a></li>
<li><a href="#the-executable">The executable</a></li>
</ul>

<h2 id="differences-that-come-from-quickjs"><a class="heading-anchor" href="#differences-that-come-from-quickjs">Differences that come from QuickJS</a></h2>
<table>
<thead>
<tr>
<th>Area</th>
<th>Effect</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Finalizer timing</strong></td>
<td>QuickJS frees an object as soon as its last reference goes away (cycles at <code>JS_RunGC</code>). Finalizers therefore usually run <strong>earlier</strong> than in Node.js, at the next loop iteration instead of at some later major GC. Code that assumes an object stays alive while only weakly referenced still works within the same macrotask (the kept-objects list), but not across macrotasks. See <a href="/projects/quickjs-napi/docs/architecture/#object-lifetime">architecture.md</a>.</td>
</tr>
<tr>
<td><strong>BigInt size</strong></td>
<td>at most 2^20 bits (16384 words; V8: 2^30). <code>napi_create_bigint_words</code> beyond that throws <code>RangeError: Maximum BigInt size exceeded</code>, as V8 does past its own limit.</td>
</tr>
<tr>
<td><strong>BigInt words</strong></td>
<td><code>napi_*_bigint_words</code> convert through a hexadecimal string: O(n), slower than V8's direct access for very large values.</td>
</tr>
<tr>
<td><strong>External strings</strong></td>
<td><code>node_api_create_external_string_*</code> always copy and run the finalizer immediately (<code>*copied = true</code>). Node.js does the same when V8 uses the pointer-compression sandbox, so addons handle it already.</td>
</tr>
<tr>
<td><strong>Property keys</strong></td>
<td><code>node_api_create_property_key_*</code> create ordinary strings: QuickJS atomizes keys itself. Not observable.</td>
</tr>
<tr>
<td><strong>External memory</strong></td>
<td><code>napi_adjust_external_memory</code> keeps the counter but does not influence garbage collection: QuickJS has no such heuristic.</td>
</tr>
<tr>
<td><strong>Basic finalizers</strong></td>
<td>all finalizers run outside the GC, so calling any Node-API function from a <code>node_api_basic_finalize</code> never triggers Node's fatal "Finalizer is calling a function that may affect GC state" error.</td>
</tr>
<tr>
<td><strong>Async context</strong></td>
<td>there is no <code>async_hooks</code>: <code>napi_async_init</code>, <code>napi_make_callback</code> and callback scopes work, but no async resource is tracked (<code>AsyncLocalStorage</code> and async stack traces do not follow native callbacks).</td>
</tr>
</tbody>
</table>
<h2 id="behaviour-that-is-defined-here-but-not-in-nodejs"><a class="heading-anchor" href="#behaviour-that-is-defined-here-but-not-in-nodejs">Behaviour that is defined here but not in Node.js</a></h2>
<p>These cases are undefined behaviour or leaks in Node.js; quickjs-napi chose a
safe behaviour:</p>
<table>
<thead>
<tr>
<th>Case</th>
<th>quickjs-napi</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>napi_delete_async_work</code> on a queued item</td>
<td>the item is freed after its <code>complete</code> has run</td>
</tr>
<tr>
<td>async work items and user references never deleted</td>
<td>freed with the env at teardown (Node.js leaks them)</td>
</tr>
<tr>
<td>a user <code>napi_ref</code> whose finalizer ran but that the addon never deleted</td>
<td>freed at teardown</td>
</tr>
<tr>
<td>a handle scope left open by a function called from JavaScript</td>
<td>closed with the call's implicit scope (warning in Debug builds)</td>
</tr>
</tbody>
</table>
<h2 id="not-provided"><a class="heading-anchor" href="#not-provided">Not provided</a></h2>
<ul>
<li><code>NAPI_EXPERIMENTAL</code> APIs: the bundled headers stop at version 10 and
declare no experimental function (<code>node_api_post_finalizer</code>, ...); an addon
that needs one fails to load because the symbol is missing.</li>
<li><code>napi_would_deadlock</code> is never returned (Node.js 22 does not return it
either); a blocking call of a full thread-safe function from the loop
thread deadlocks.</li>
</ul>
<h2 id="the-executable"><a class="heading-anchor" href="#the-executable">The executable</a></h2>
<p>The <code>quickjs-napi</code> executable is not Node.js; it provides what addon packages
and their tests need (<a href="/projects/quickjs-napi/docs/host/">host.md</a>). In particular:</p>
<ul>
<li><code>process.version</code> is <code>v22.23.4</code> (the reproduced Node-API behaviour) but
<code>process.versions.node</code> is not set;</li>
<li>CommonJS only: no ES modules, no <code>package.json</code> <code>"exports"</code> maps;</li>
<li>no <code>worker_threads</code>, <code>async_hooks</code>, <code>domain</code>, <code>fs</code>, <code>net</code>, <code>http</code>,
<code>crypto</code>;</li>
<li><code>child_process</code> without a shell, and an asynchronous child's stdin is never
a pipe.</li>

19:Tbbcd,<h1 id="embedding-api-qjsnapih">Embedding API (<code>qjsnapi.h</code>)</h1>
<p>The library <code>qjsnapi</code> can be embedded in any application that uses QuickJS.
<code>include/qjsnapi.h</code> is its whole public interface besides Node-API itself.
The <code>quickjs-napi</code> executable (<a href="/projects/quickjs-napi/docs/host/">host.md</a>) is one such embedder, and
<code>test/unit/test_embed.c</code> is a complete, tested example.</p>
<ul>
<li><a href="#lifecycle-at-a-glance">Lifecycle at a glance</a></li>
<li><a href="#minimal-embedder">Minimal embedder</a></li>
<li><a href="#function-reference">Function reference</a></li>
<li><a href="#embedder-responsibilities">Embedder responsibilities</a></li>
<li><a href="#linking">Linking</a></li>
</ul>
<h2 id="lifecycle-at-a-glance"><a class="heading-anchor" href="#lifecycle-at-a-glance">Lifecycle at a glance</a></h2>
<pre class="mermaid">sequenceDiagram
    participant E as embedder
    participant Q as QuickJS
    participant H as qjsnapi host
    participant U as libuv loop
    E->>Q: JS_NewRuntime, JS_NewContext
    E->>H: qjsnapi_host_create(ctx) (or _with_loop)
    E->>H: set_uncaught_handler, set_checkpoint (optional)
    E->>H: qjsnapi_load_addon / qjsnapi_init_static_addon
    H-->>E: exports
    E->>Q: run scripts that use the exports
    E->>U: uv_run(qjsnapi_host_get_loop(host), UV_RUN_DEFAULT)
    U->>H: async work, thread-safe functions, finalizers
    E->>Q: JS_FreeValue(exports)
    E->>H: qjsnapi_host_destroy (cleanup hooks, drain, finalizers)
    E->>Q: JS_FreeContext, JS_FreeRuntime
</pre>
<p>The rules are:</p>
<ul>
<li><strong>One host per <code>JSContext</code>.</strong> The host is stored as the context opaque
(<code>JS_SetContextOpaque</code>), so the embedder must not use that slot for anything
else. <code>qjsnapi_host_from_context</code> gets it back.</li>
<li><strong>One thread.</strong> The context and the loop run on the same thread. Other
threads only reach the host through thread-safe functions and async work.</li>
<li><strong>Destroy before <code>JS_FreeContext</code>.</strong> <code>qjsnapi_host_destroy</code> still needs the
context to finalize references.</li>
</ul>

<h3 id="host-lifecycle"><a class="heading-anchor" href="#host-lifecycle">Host lifecycle</a></h3>
<h4 id="qjsnapi_host_create"><a class="heading-anchor" href="#qjsnapi_host_create"><code>qjsnapi_host_create</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#6F42C1;--shiki-dark:#B392F0">qjsnapi_host_create</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(JSContext </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">ctx</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Creates the Node-API host for <code>ctx</code>, with a <strong>libuv loop of its own</strong> that
<code>qjsnapi_host_destroy</code> closes. It captures the builtins Node-API needs,
evaluates the embedded <code>Buffer</code> class, probes the builtin class IDs and
registers the library's loop handles. Must be called before any user script
runs (see <a href="/projects/quickjs-napi/docs/architecture/#captured-builtins">captured builtins</a>).
Returns <code>NULL</code> on failure; a JavaScript exception may then be pending.</p>
<h4 id="qjsnapi_host_create_with_loop"><a class="heading-anchor" href="#qjsnapi_host_create_with_loop"><code>qjsnapi_host_create_with_loop</code></a></h4>

<h4 id="qjsnapi_host_destroy"><a class="heading-anchor" href="#qjsnapi_host_destroy"><code>qjsnapi_host_destroy</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_host_destroy</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Tears down every env as Node.js does at exit, with JavaScript disabled:</p>
<ol>
<li>cleanup hooks, newest first (thread-safe functions start closing, async
cleanup hooks start);</li>
<li>queued async work cancelled;</li>
<li>the loop runs until in-flight work, thread-safe functions and async cleanup
hooks are done;</li>
<li>references and instance data finalized;</li>
<li>the module cache released and the host detached from the context.</li>
</ol>
<p>The embedder closes its own handles on the loop first. Must be called before
<code>JS_FreeContext()</code>. The full order is described in
<a href="/projects/quickjs-napi/docs/architecture/#teardown">architecture.md</a>.</p>
<h3 id="loading-addons"><a class="heading-anchor" href="#loading-addons">Loading addons</a></h3>
<h4 id="qjsnapi_load_addon"><a class="heading-anchor" href="#qjsnapi_load_addon"><code>qjsnapi_load_addon</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">int</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_load_addon</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">const</span><span style="color:#D73A49;--shiki-dark:#F97583"> char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">path</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, JSValue </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">exports</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Loads a <code>.node</code> shared library and runs its Node-API initializer.</p>
<ul>
<li>Returns <code>0</code> and stores a <strong>new reference</strong> to the exports in <code>*exports</code>; the
caller frees it.</li>
<li>Returns <code>-1</code> with a JavaScript exception pending on the context. Its <code>code</code>
property is <code>MODULE_NOT_FOUND</code> (the path cannot be resolved) or
<code>ERR_DLOPEN_FAILED</code> (the library cannot be opened, does not register a
module, or needs a Node-API version above 10). A legacy module registered
without an init function fails with <code>Module has no declared entry point.</code>
and no code, as in Node.js. An exception thrown by the initializer is left
pending as it is.</li>
<li>Like <code>process.dlopen</code>, <strong>every call runs the initializer again</strong> with a new
env and returns new exports. Caching by path is the module loader's job.</li>
<li>Fails while the host is being destroyed.</li>
</ul>
<p>The entry point is resolved as described in
<a href="/projects/quickjs-napi/docs/architecture/#loading-addons">architecture.md</a>.</p>
<h4 id="qjsnapi_init_static_addon"><a class="heading-anchor" href="#qjsnapi_init_static_addon"><code>qjsnapi_init_static_addon</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">int</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_init_static_addon</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, </span><span style="color:#D73A49;--shiki-dark:#F97583">const</span><span style="color:#D73A49;--shiki-dark:#F97583"> char</span><span style="color:#D73A49;--shiki-dark:#F97583"> *</span><span style="color:#E36209;--shiki-dark:#FFAB70">name</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#24292E;--shiki-dark:#E1E4E8">                              napi_addon_register_func </span><span style="color:#E36209;--shiki-dark:#FFAB70">init</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">                              int32_t</span><span style="color:#E36209;--shiki-dark:#FFAB70"> module_api_version</span><span style="color:#24292E;--shiki-dark:#E1E4E8">, JSValue </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">exports</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Runs the initializer of an addon <strong>linked statically</strong> into the embedder, as
if it had been loaded from <code>name</code>. <code>module_api_version</code> follows the

name</strong>: a second call with the same name returns a new reference to the same
exports object without running <code>init</code> again. <code>node_api_get_module_file_name</code>
reports <code>name</code> for such an addon.</p>

<h3 id="finalizers-and-weak-references"><a class="heading-anchor" href="#finalizers-and-weak-references">Finalizers and weak references</a></h3>
<h4 id="qjsnapi_host_run_finalizers"><a class="heading-anchor" href="#qjsnapi_host_run_finalizers"><code>qjsnapi_host_run_finalizers</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">size_t</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_host_run_finalizers</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Runs the queued finalizers of every env (objects collected by the GC that
have a <code>napi_wrap</code>, <code>napi_add_finalizer</code>, external value, external

<p>Non-zero while finalizers are queued: an event loop that decides itself when
to stop must not exit yet.</p>
<h4 id="qjsnapi_host_clear_kept_objects"><a class="heading-anchor" href="#qjsnapi_host_clear_kept_objects"><code>qjsnapi_host_clear_kept_objects</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_host_clear_kept_objects</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">);</span></span></code></pre>
<p>Releases the <em>kept objects</em>: the targets of references that became weak,
held strongly until now to reproduce V8's "alive until the next GC" (see
<a href="/projects/quickjs-napi/docs/architecture/#kept-objects">architecture.md</a>). The library clears the list

closes with no JavaScript below it: where Node.js runs its tick and microtask

jobs (<code>JS_ExecutePendingJob</code>) and reports their exceptions to the uncaught
handler. An embedder with a <code>process.nextTick</code> queue or rejection tracking
installs its own (the executable does: <code>host_checkpoint</code> in <code>host/main.c</code>).</p>
<h4 id="qjsnapi_host_set_force_uncaught_exceptions_policy"><a class="heading-anchor" href="#qjsnapi_host_set_force_uncaught_exceptions_policy"><code>qjsnapi_host_set_force_uncaught_exceptions_policy</code></a></h4>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">void</span><span style="color:#6F42C1;--shiki-dark:#B392F0"> qjsnapi_host_set_force_uncaught_exceptions_policy</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi_host </span><span style="color:#D73A49;--shiki-dark:#F97583">*</span><span style="color:#E36209;--shiki-dark:#FFAB70">host</span><span style="color:#24292E;--shiki-dark:#E1E4E8">,</span></span>

<p>Node's <code>--force-node-api-uncaught-exceptions-policy</code> (default off). When off,
an exception thrown by a thread-safe function callback of an addon built for
Node-API &#x3C; 10 becomes a <code>DEP0168</code> deprecation warning instead of an uncaught
exception. When on, it is always an uncaught exception.</p>
<h2 id="embedder-responsibilities"><a class="heading-anchor" href="#embedder-responsibilities">Embedder responsibilities</a></h2>
<table>
<thead>
<tr>
<th>Responsibility</th>
<th>How</th>
</tr>
</thead>
<tbody>
<tr>
<td>Run the loop</td>
<td><code>uv_run(qjsnapi_host_get_loop(host), ...)</code>; it runs async work completions, thread-safe function calls and queued finalizers.</td>
</tr>
<tr>
<td>Report uncaught exceptions</td>
<td><code>qjsnapi_host_set_uncaught_handler</code>.</td>
</tr>
<tr>
<td>Drain the embedder's own queues</td>
<td><code>qjsnapi_host_set_checkpoint</code> (microtasks, <code>nextTick</code>, unhandled rejections).</td>
</tr>
<tr>
<td>End macrotasks</td>
<td><code>qjsnapi_host_clear_kept_objects</code> after each macrotask it runs itself, and before <code>JS_RunGC</code>.</td>
</tr>
<tr>
<td>Expose <code>Buffer</code></td>
<td><code>qjsnapi_host_get_buffer</code>, if scripts should see it.</td>
</tr>
<tr>
<td>Cache modules</td>
<td><code>qjsnapi_load_addon</code> never caches; <code>require</code> does.</td>
</tr>
<tr>
<td>Tear down in order</td>
<td>close the embedder's handles, <code>qjsnapi_host_destroy</code>, then <code>JS_FreeContext</code>, <code>JS_FreeRuntime</code>.</td>
</tr>

<td>Export the symbols</td>
<td>addons resolve <code>napi_*</code> and <code>uv_*</code> from the process (see below).</td>

<h2 id="linking"><a class="heading-anchor" href="#linking">Linking</a></h2>
<p>Addons do not link against the library: they find <code>napi_*</code> and <code>uv_*</code> in the
process. The executable that embeds the library must therefore <strong>export</strong>
them:</p>
<table>
<thead>
<tr>
<th>Platform</th>
<th>What is needed</th>
</tr>
</thead>
<tbody>
<tr>
<td>Linux, BSD</td>
<td>link the library as a whole archive and export dynamic symbols (<code>--export-dynamic</code>, CMake <code>ENABLE_EXPORTS</code>).</td>
</tr>
<tr>
<td>macOS</td>
<td>whole archive (<code>-force_load</code>); addons are linked with <code>-undefined dynamic_lookup</code>.</td>
</tr>
<tr>
<td>Windows (MinGW)</td>
<td>whole archive; the definitions carry <code>__declspec(dllexport)</code> (<code>NAPI_EXTERN</code>; libuv is built with <code>BUILDING_UV_SHARED</code>). node-gyp addons import from <code>node.exe</code> and are redirected to the running process by node-gyp's delay-load hook.</td>
</tr>
</tbody>
</table>
<p><code>CMakeLists.txt</code> does all of this for the <code>quickjs-napi</code> target; an embedder
can copy that setup. <code>tools/check_exports.py &#x3C;executable></code> verifies that every
Node-API function is exported.</p>
<p>Link with <code>uv_a</code> (libuv) and the QuickJS library the headers in <code>include/</code>
were taken from.</p>
<h3 id="from-a-release-package"><a class="heading-anchor" href="#from-a-release-package">From a release package</a></h3>
<p>The <a href="/projects/quickjs-napi/docs/building/#release-packages">release packages</a> install a CMake
package:</p>
<pre class="shiki shiki-themes github-light github-dark" style="background-color:#fff;--shiki-dark-bg:#24292e;color:#24292e;--shiki-dark:#e1e4e8" tabindex="0"><code><span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">find_package</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(qjsnapi CONFIG REQUIRED)   </span><span style="color:#6A737D;--shiki-dark:#6A737D"># CMAKE_PREFIX_PATH=&#x3C;package dir></span></span>
<span class="line"><span style="color:#D73A49;--shiki-dark:#F97583">target_link_libraries</span><span style="color:#24292E;--shiki-dark:#E1E4E8">(my_app </span><span style="color:#6F42C1;--shiki-dark:#B392F0">PRIVATE</span><span style="color:#24292E;--shiki-dark:#E1E4E8"> qjsnapi::static)   </span><span style="color:#6A737D;--shiki-dark:#6A737D"># or qjsnapi::shared</span></span></code></pre>
<table>
<thead>
<tr>
<th>Target</th>
<th>What it is</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>qjsnapi::static</code></td>
<td><code>libqjsnapi.a</code> + the bundled <code>libqjs.a</code> and <code>libuv.a</code>, with their system libraries</td>
</tr>
<tr>
<td><code>qjsnapi::core</code></td>
<td><code>libqjsnapi.a</code> alone, to link <strong>your own</strong> QuickJS and libuv</td>
</tr>
<tr>
<td><code>qjsnapi::quickjs</code>, <code>qjsnapi::uv</code></td>
<td>the bundled <code>libqjs.a</code> and <code>libuv.a</code></td>
</tr>
<tr>
<td><code>qjsnapi::shared</code></td>
<td>the shared library (<code>libqjsnapi.so</code>, <code>libqjsnapi.dylib</code>, <code>qjsnapi.dll</code>)</td>
</tr>
<tr>
<td><code>qjsnapi::addon</code></td>
<td>usage requirements of a <code>.node</code> addon for the <code>quickjs-napi</code> executable</td>
</tr>
<tr>
<td><code>qjsnapi::quickjs-napi</code></td>
<td>the executable</td>
</tr>
</tbody>
</table>
<p><code>test/package/CMakeLists.txt</code> uses each of them; it is what the release
workflow runs on every package.</p>
<p><strong>Static: three archives.</strong> QuickJS and libuv are separate archives so that
an embedder can replace them (<code>qjsnapi::core</code> plus its own libraries). The
replacements must be ABI-compatible with the headers of the package: the same
QuickJS release (<code>quickjs.h</code> defines the layout of <code>JSValue</code>) and a libuv 1.x
not older than the bundled one (<code>BUILDINFO.txt</code> has both versions). The rules
of the table above still apply: to load addons, the executable must link
<code>libqjsnapi.a</code> and libuv as whole archives and export their symbols.</p>
<p><strong>Shared.</strong> The shared library contains QuickJS and libuv and exports
<code>napi_*</code>, <code>uv_*</code>, <code>qjsnapi_*</code> and the QuickJS API (<code>JS_*</code>, <code>js_*</code>). Create the
<code>JSRuntime</code> and <code>JSContext</code> with the QuickJS <strong>of the library</strong>: do not link
another QuickJS in the same process (two copies do not share class IDs and
atoms, and values cannot cross between them). Limits:</p>
<ul>
<li><strong>Windows:</strong> node-gyp addons import Node-API from <code>node.exe</code>, and their
delay-load hook redirects that to the <em>executable</em> of the process, not to
<code>qjsnapi.dll</code>: they cannot load in a program that uses the DLL. Use the
static archives (exporting the symbols from the executable, as above), or
<code>quickjs-napi.exe</code>. Addons linked against <code>libqjsnapi.dll.a</code> instead load
normally.</li>
<li><strong>Linux, BSD, macOS:</strong> addons find the symbols in the shared library, which
is loaded globally with the executable; nothing else is needed.</li>
